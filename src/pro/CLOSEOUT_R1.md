## 本轮实际产品修复

### 人工整理与日常界面

- 复杂对话框保留拆分/Series草稿，防重复点击，晚到的保存结果不关闭后来打开的面板。Series调整保留已经确认的序号、分支和断点。
- 搜索具有完整结果分页与版本核对。搜索提供有限的命名主题快捷入口及“查看全部名称与关联”；关联编辑跨页显示全部关系和排除，并保留未保存标题与选择。
- 建议展示具体旧/新名称、目标主题、主关系和成员；失效建议不能应用。超出单次完整审阅范围的保留建议可查看、拒绝并重新按小批核对，不能通过截断内容盲目确认。
- 合并/拆分冲突解释实际聊天、原排除、映射目标、锁和工作线；大冲突集明确显示总数与当前展示数量，处理后重新预览。冲突仍在时不生成可执行确认。
- 模型任务、历史名称、操作记录与高级设置放在明确入口。历史名称可逐个明确移除，操作仍可撤销；不会因为长期改名到达100别名后永久无法编辑。
- 过期会员保留已有资料、读取、清理和撤销。人工写入及自动写入均在数据库写入回调中再次检查当前许可。
- 真正的 Chrome 标签页100%、125%、200%缩放、短窗口、键盘焦点、连续点击、长列表、侧栏失败及重开已纳入可执行浏览器回归。字体由测试运行环境提供，不另起视觉系统。

### 生产整理与模型准备

`production-owner.mjs` 使用 `organize/local-runner.mjs` 的实际本地规则，独立于演示的 fixture-rules。中文词汇、明确对象/任务、新旧版本冲突和歧义有反例测试；本地规则始终作为可审建议，不计为真实模型分类质量。

每次最多处理10条已确认、获准的聊天。会话游标覆盖整个可整理范围，未知结果也推进游标，后续聊天不会被前十条阻塞。每个云任务冻结该批引用，后续重新读取仍核对同一批、全部版本和作用域。相同明确主题种子可以合并为一条多成员建议，近似名称不据此自动合并。

标题、别名与候选意图在严格字节预算内投影，省略可选内容会明确标记截断；原数据不变。供应商只收到本次允许的最小数据和不透明句柄，回复必须通过严格 schema、句柄、证据和语义校验。

模型桥复用 DB4 的预算/任务账本：预留、派发、费用与任务状态持久化。发送前在同一事务核对 Native/Evidence/Workspace/Pro 根和当前许可；结果应用再执行相同资产 CAS。UI 的六秒请求只启动/观察任务，有限的模型等待不续期页面授权，不设保活服务。中断或重启后的未知派发不会自动重发或自动退款。

模型配置过期、用途撤回或供应商关闭后，旧费用与任务仍可查看、取消和恢复。任务分页覆盖全部在册任务；明确恢复核对已保存的操作收据，不重新运行模型或资产命令。每次恢复的核对数量有界，重复核对继续处理剩余项。

用户在“模型与预算”明确选择单次、当日和当月上限，默认均为0。金额按六位小数的整数微货币校验；日/月周期明确采用 UTC。界面显示已占用金额与队列剩余额度，包含预留和未知费用，并继续受当前付款配置更严格的安装/空间限额约束。调整先展示旧值和新值，明确确认后同库保存；取消不写入，失效或重复确认不会覆盖新选择。到限硬停，临近上限提供暂停和调整。提高预算不隐式启用云处理；任何调整均暂停所有空间的当前云许可，须重新确认。

首次云确认把数据外传和自动资产变更分开选择。只有当前可信模型政策与完整质量门都就绪，才显示默认不勾选的自动选项。开启时只记住当前已有集合，不静默整理全部历史；以后 Free 已接纳的新引用才进入有限 RAM 队列，按每个 C 一次任务处理。完成通知促使已有工作区刷新后处理下一项，失败不自动重发，不扫描宿主、不设定时保活。每任务至多一笔合格自动事务；同 C 的其他变化仍可审阅，不重复收费重跑。

“切换到原生视图后继续当前范围”是另一项默认关闭的选择。明确允许后，只在同一文档当前授权仍有效时保留原组织范围；选择不同 Project 范围、撤权、关闭处理或变更预算都会撤销。它不承诺关闭浏览器后仍运行。单聊天的“精细复核”另有实际数据/费用预览，使用同一冻结模型且只产生建议，不开启全局云模式，不应用自动资产，也不悄悄切换更贵模型。

### 可信接入接口

扩展默认不传 `modelProvider`。未来接入由可信 worker 所有者提供：

| 私有字段/回调 | 用途 |
|---|---|
| `enabled`、`configuration` | 固定供应商、模型、prompt、schema、输入种类、价格卡、每任务上限。配置不能携带API密钥或任意端点。 |
| `disclosure` | 供应商名称、政策版本/官方链接及保留说明；未提供时不能从界面启用云整理。首次启用显示实际最小数据示例和每次费用上限，确认绑定当前来源、范围和一次性预览。 |
| `canUse(context)` | 同步核对当前目的、账号/空间、本次数据用途许可与已授予的固定供应商可选主机权限。 |
| `authorizeDispatch(context, details, signal)` | 在发送前核对当前授权与最小出站预览，临时返回凭据。凭据不进入frame、任务、日志或备份。 |
| `transport` | 明确注入的传输实现；没有隐式全局fetch回退。 |
| `automation.policy`、`automation.isCurrent`（可选） | 可信当前质量评测、首轮状态与显式自动范围；同步有效性检查贯穿资产事务。未提供时仅生成建议。 |

frame只可通过一次性预览选择三项用户限额；不能提交任意政策、窗口、付款身份、供应商地址、退款或对账命令。可信管理所有者可再施加更严格的付款限额。真实供应商价格、凭据、数据目的、保留政策及实际调用必须获准；`store:false` 不被描述为供应商零保留。可信配置在运行中变化会使旧确认、发送和迟到写入失效；预算政策在同一资产事务再次核对，不能利用异步检查后的间隙提交旧结果。

自动整理接线已经具备：只允许完整质量报告、冻结模型绑定、合格独立lane、用户当前范围的自动选择、可信用途许可、非首轮、无人工保护冲突的低风险提案；每个任务至多一笔自动资产事务，保留完整 inverse 与来源。页面传入 `APPLY_LOW_RISK_PROPOSAL` 仍被拒绝。合成质量报告只用于控制流测试，不作为自然样本或资格证明；本候选不内置获批质量报告。

## 长期稳定性与升级

仍使用 DB4 现有 object stores，不新增数据库或提升数据库版本。完整细节见 [HISTORY.md](integration/HISTORY.md)。

- 活跃操作窗口达到512笔后，追加密封历史段，保存旧检查点、全部原日志、inverse和校验。旧操作查询、分页、重放和撤销继续可用，超过原10,000笔寿命上限仍可正常编辑。
- 账本仅归档已终结且所有原费用窗口已结束的任务/预留，保留精确历史结算总额与ID退役保护；不删除未知费用、预留费用和仍适用的账期。
- 可操作提案保留明确上限；旧终结与已证失效机器记录可从活跃表移出，其原始内容仍在事务历史中。旧自动/人工接受操作撤销时，可从完整收据恢复语义拒绝，避免机器再次提出同一工作。
- 损坏恢复保留原始损坏记录、已验证历史和不可变收据；后续再次损坏仍可执行新的明确恢复。每笔后续资产事务同时更新持久最高序号、revision与根校验；当前根和最后日志一起丢失时，旧恢复收据不能伪装成最新状态。证据不足时明确拒绝恢复，零回退写入。
- 分段资产根使用 storage/2，经历修复的根使用 storage/3，并在分段/复合恢复后保留该最低reader；用户预算账本使用独立的 billing-storage/3。旧 Pro reader明确拒绝不支持的根；旧 Free忽略Pro命名空间。DB4版本和object stores不变，便携数据备份仍保持原统一 /1 codec，只保存数据资产，不携带凭据、许可、队列、未知费用或完整历史。不可将旧 Pro 覆盖安装后能读Free误称为完整降级支持。
- 容量/配额错误只向当前授权界面返回有限的用户错误类别，不传播原始异常、个人数据或供应商信息。失败事务保持零部分写入，重试仍沿用原操作ID核对结果。
