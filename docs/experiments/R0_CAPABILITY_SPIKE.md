# R0：影响架构的能力验证任务书

状态：READY_FOR_SCOPED_AUTHORIZATION；当前文档任务不执行探针。下一轮给 Codex 的首选任务，不重新调研完整产品、不重做原型、不先搭正式扩展。

## 1. 本轮要回答的六个问题

能否证明当前网页的账户/原生空间？能否把路由与可见用户消息可靠绑定？历史能发现到什么程度？同 scope 跨 Project 聚合是否能保留真实来源？增强/失效后原生能力是否保留？与实际 PAIA 版本共存是否安全？

这些是能力问题，不是视觉批准问题。不能用纯合成 UI 回答 live ChatGPT 的问题，也不能为了通过改用用户私人账户或内部 API。

## 2. 授权、目录与环境

未来仅在用户另行允许后，写 `experiments/r0/**`、`tests/r0/**` 和 `docs/experiments/results/**` 的隔离探针/fixture/报告。不创建正式产品 runtime、会员、模型/同步服务，不修改其他仓库；单独实验分支与 Draft PR，不自动合并。

使用隔离 Chrome profile 和明确获准的清洁测试账户，所有项目/对话仅合成内容。不得拷贝日常 profile、cookies/token；不得默认已登录账户可测试。正式双账户正向测试需要两套获准的 clean identities；没有就将对应 live 项 BLOCKED，不拿两个内存 store 替代。

预设样本：普通聊天 T0；Project P1 的 T1；Project P2 的 T2；同名不同事项 T3；长内容/分支 T4；未打开且不在当前侧栏的 T5；另一账户/原生组织的冲突名 T6；shared/temporary 示例按能力可用情况单列。创建真实原生样本由用户在清洁环境完成，或另行显式授权单独 fixture setup；R0 探针本身不自动发送、移动、删除、改名或批量翻历史。

原生发送等功能的对照可由获准操作者手工在合成账户完成；若连这些操作未获准，就只测试无副作用部分并明确剩余 NOT_RUN。屏幕/DOM/网络捕获只限批准的 clean fixture；公开提交只含合成/脱敏证据。

## 3. R0-00：盘点与准入

读精确 main/本提案，记录 Chrome/OS/页面语言/布局/扩展 ID 与构建 hash、host 变体、所有权限及测试账户范围。预先列出每个采集渠道、数据角色、持久/外传与必要性。

只对会改变实验安全或架构的既有来源做定向复核：官方 export、账户切换、API 会话/登录范围、Chrome lifecycle/storage/权限与平台条款。不是重新做竞品研究；动态文档要记录读取日期与实际内容。不据旧报告的 URL 推定当前资格。

默认不申请 cookies/debugger/history/all_urls，不进行 paid/network model 调用，不假设有历史 API。环境限制先报告，不关闭系统安全设置、重启用户工作浏览器或反复绕过。

## 4. R0-01：范围身份，最优先

候选证据必须来自获准、可观察且可复验的宿主身份，记录信息来源和稳定性；没有发现就如实记录。区分 account/native organization 与 Project，区分 OAuth 与当前网页，禁止把手选 vault 当通过方案。

实验序列：A→B→A、同名账户/项目标签、原生组织切换、多个 tab 同时存在、SPA 过渡、后退/前进、后台冻结唤醒、旧异步观察/索引/模型候选延迟到新 epoch。至少有正向同 scope 识别与反向拒绝，不仅负例全部关闭。

断言：未知/切换中先移除敏感投影；晚回包不得写入/显示；每份存储/索引/回执均有正确 scope；无跨 scope 云/native 通道（本探针保持关闭）。零观测污染必须附用例范围，不能宣传绝对安全。

裁决：能可靠绑定才给该环境 GO；只能证明受限运行模式给 LIMITED 并写可执行限制；关键 witness 无法成立则自动跨账户持久投影 NO_GO/BLOCKED。独立 Chrome profile 可以降低混用风险，但仍需证明宿主 scope，不能直接绕过门槛。

## 5. R0-02：历史与路由—渲染所有权

先 title/reference-only，再在 scope 成立且获准后试用户角色。覆盖 root→新对话、普通 route、Project route、快速换聊残留 DOM、虚拟化/折叠、编辑/分支、旧页面延迟观察。记录 nativeConversationId 与已渲染消息是否能形成唯一一致证据；URL 一变就读取旧 DOM 的方案必须被反例击穿。

T5 未打开时，验证系统不会声称见到其全文/全账户计数；用户主动原生搜索并打开后，才按新观察补全。记录 sidebar、搜索结果、当前正文与导出分别提供什么，不用隐藏 tab 或内部 endpoint 补齐。

官方导出只用获准 clean-account 文件；实际格式/分支/Project 字段未知要保留 unknown。重复、无效编码、重复 ID、缺字段、恶意 ZIP 使用合成反例。只验证 schema/快照范围，不宣称官方导出永久结构固定。

单列结果：reference discovery、user-message ownership、branch identity、native Project observation、export coverage。任一未证不影响其他已有证据，但不得从 title 成功推断 body 成功。

## 6. R0-03：跨 Project 引用

仅同一已验证 scope 的 T0/T1/T2 组成合成工作区。打开每条仍用真实原生链接；手工/探针观察原生 Project 信息前后相同，派生名与原名分离。跨其他账户/组织引用必须拒绝。

对比普通聊天与 P1/P2 中的新建入口：只验证目的地可达/可辨，不由探针创建真实消息。不把同一工作区显示解读为文件/指令/记忆已经合并，不通过读取项目私有文件来证明。

未能证明来源字段时显示“未知”，该对象不得进入 native-write 演示以外的执行。shared URL 保持独立类型，不能映射成用户自有 conversation。

## 7. R0-04：原生 DOM 岛与恢复

先无扩展 baseline，再最小探针。仅挂载/移除带 VAIWL 名称空间的导航，保留原生 transcript/composer 引用和活动元素证据，不复制正文、不读草稿。用合成输入人工检查输入/IME/焦点/selection/滚动以及模型/附件/工具菜单、Canvas/语音等当前可用入口。

矩阵：受控派生→原生；SPA DOM 重建；worker 终止/重连；扩展 reload；disable→原生可用→re-enable/reload/refresh→重连→再投影；后台节流；页面 freeze/resume；CSS 失效；减少动态；窄屏/缩放。记录具体操作顺序和实际结果，不把不同版本的半条链拼成一次完整通过。

检测 shell 自有属性是否撤掉、原生当前样式是否未被旧字符串覆盖、隐藏导航是否仍可 Tab 到、menu portal 是否被遮。租约过期须分别测原生可操作和干净布局；后台时钟/动画不能先验保证。

禁止自动刷新来制造恢复 PASS。必要刷新是用户可选逃生步骤，先记录失效/残留/草稿和未完成任务风险。只在合成 clean 账户中观察；真实数据不能作为实验燃料。

裁决：若完整导航替换不稳，提出缩小挂载区域/能力级退回，而不是重写完整 ChatGPT；若恢复不成立，不开启该隐藏策略。

## 8. R0-05：PAIA 共存必须前置

记录 PAIA 实际加载构建，不能拿原研究的 0.43.4 或最新 main 当已安装。无 PAIA、PAIA 单独、探针单独、共存四组；加载顺序反转、双方 reload/disable、导航原生切换、PAIA 浮板展开/搜索、原生输入增高、IME 和菜单都测。

断言：VAIWL 不读写 PAIA 私有库/DOM，不接管提示词板，不遮 composer，不引发重复导航/重排/焦点丢失。双方独立退出保持另一方可用。没有现成占用协议时，测试 VAIWL 保守退让而非发明“已支持消息协议”。

ACS/CTM 共存用干净实验检查冲突识别/拒绝，不启用实际 native writer，不自动关停第三方扩展。需要跨库改动就报告协议需求，不能在该任务修 PAIA。

## 9. R0-06：结果与停止规则

交付：能力矩阵、读取渠道/覆盖表、账户正反例、原生保留/生命周期结果、PAIA 共存矩阵、最小权限表、源码/构建 hash、环境、失败记录及架构裁决。日志默认无正文、真实标题/邮箱/ID；只提交合成证据。每条注明 BROWSER_FIXTURE 或 LIVE_HOST，不混计。

有限策略：同一环境障碍不反复重试；失败先定位可变原因，修正后新版本重测保留旧结果；无法定位就 BLOCKED 或缩小支持范围。不扩大采集、不申请隐藏权限、不降低测试数据与断言、不把局部失败变成无限审计循环。

退出不是全打绿才有报告：逐项 GO/LIMITED/BLOCKED/NO_GO；明确哪些 B/C 任务可开始、哪些能力关闭、是否需用户决策。完成报告后停止，不自动实施 B、不重写产品设计、不生成第二版原型。
