## 2. 继承PR #14的限制，不重复虚构时间

PR #14在所检访客DOM、初始化及自然NDJSON中仍未得到可验证原始user-send timestamp；TimeCoverage也UNKNOWN。它没有穷尽所有匿名渠道，不等于“必须登录才有所有信息”或“ChatGPT没有时间”。HTTP Date、浏览器观察、revision/status不是消息发送时间。

访客刷新/重开丢失，Back可见旧DOM但路由不一致；marker存在不能证明当前对话。继续按原生会话/消息/分支/route/role分别核验，不能由截图相似来认证恢复。

本轮不追加发送；后续每个实验开工前固定**跨所有run/Profile/目录的总预算**。PR #14已出现曾声明6条但累计9条的边界问题，之后第10条被拒绝，禁止用换命令/路径重置。明确限次许可未取得则只设计或离线验证，不启动浏览器。

## 3. 最小先验和实验顺序

先确认合法可持续渠道与scope证据，再阅读身份有关的来源；清洁测试账户是某些能力的条件，不要求所有无登录实验重新登录。guest能力与持久账户/Project能力分别记录。

Project流程的最小真实实验：用户选择一个干净scope，确认预算（建议最多1个Project、1次打开新聊天、发送0）；只验证创建/读回/取消/未发送时无conversationId不伪关联。首条消息后归属须另给发送许可，不能由“测试项目创建”推出发送许可。双账户/共享Project需要另有可用样本，缺失标BLOCKED，不临时借用日常账号。

字段测试保留T0普通、P1/T1与P2/T2、同名T3、分支T4、未打开T5、另scopeT6、共享/临时可用条件。新增：两同名Project、已建Project后本地失败、空主题、单窗口、同一主题多Project、密度未知、所有主题近7天都活跃、首建并发/worker中断。

## 4. 时间/密度证据专项 R0-02.28

每条候选来源记录原始字段及语义、scope/conversation/message/branch、role/committed、时间精度/偏移、edit/branch稳定性、覆盖范围/completeThrough、撤权和重复冲突。纯source名称、`verified:true`或哈希不能自行认证。

对候选H判断N(H)的正向证据和潜在未知数。少量已知主题≠用户低活跃；未知发现范围或大批未分类会使扩展选择失真。不能把今日lastSend套回历史锚点；需要当时rollup或完整事件证明。

原30日用例保留为H=30兼容子集，增补7/14/60/90、month-end/DST/leap-day、相邻互斥、H/T/Z变更和policyEpoch。父卡、子窗口、历史边界必须同一快照，人工/原生数据不变。算例通过仅为规则证据，不认证真实用户密度。

## 5. 原生Project专项 R0-03.28

验证read-only发现/已知ID链接/原生UI创建/自动可执行能力分别成立。API平台`organization/projects`不算ChatGPT网页API；未经文档支持的内部history/project接口不能作为默认产品路线。

精确检查：名称不是主键、原生Project权限/共享/记忆/工具状态、点击创建前后目标一致、结果未知不重试、默认目的地CAS、用户改名/切scope/权限撤回时停止。Project已创建与对话已保存分开，复制/移动旧对话均未授权。

删除或重建Project不是自动失败补偿。无自动化能力时测试原生UI辅助路径并明确LIMITED，不把虚拟容器冒充真实项目成功。

## 6. 原生保留与恢复 R0-04/05.28

只挂自有导航/确认控件，保留真实正文/输入/模型/菜单/上传/Canvas/语音/交互回复节点、事件和状态。无字返回只有一个；不能为第一句话另造composer。原生搜索/快捷键/dot/固定/待批准/未知入口完整可达。

切H、创建pending、split/merge、旧回包、后台/可见、worker停止、reload、disable/re-enable、freeze/resume各有独立链条。分别记录原生可用、布局干净、数据保留、原生动作停止；不能拼不同版本的半条链。不能自动刷新有草稿页面来制造恢复PASS。

PAIA占位不算PAIA本体；需实际构建版本、四组baseline/单独/共同/反向加载，检查浮板、原生输入增高、菜单、焦点、双方退出。需要对方改代码时只报告，不跨库修复。
