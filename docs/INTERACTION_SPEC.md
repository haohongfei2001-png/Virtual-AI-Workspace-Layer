# VAIWL 交互规格 · v2.8候选整合

**待用户审核，未改运行时。** 三项机制以[CORE_MECHANISMS_V2_8](CORE_MECHANISMS_V2_8.md)为唯一入口。保留批准v2.7的视觉与原生所有权；本页给出增量操作，不另建原型、顶栏或管理后台。

## 1. 日常界面不重新增加管理负担

一个主题一张主页静态卡片，内部紧凑窗口行；主题/窗口靠容器、头区、图标、缩进区分，不只字号粗细。主页主题不折叠，侧栏主题按原规则折叠。旧窗口左侧小箭头只展开已确认较早窗口，不夹带容量溢出或时间未知。

近期容量沿用已归档v2.7基准5行/+12增量，更多近期内容与旧窗口分开。主界面不常驻日期、来源、统计、跨度文字、“以前”或“自动·14天”。上下区间用已有窄幅chevron：最新仅向下，历史向上/向下；aria-label、tooltip、focus仍有意义，不能仅给读屏读“按钮”。

已知未分类、时间未知、缺失/无权引用保留原生搜索、已知查找、当前上下文和初次整理预览的可达路径，不恢复“以前/全部主题/其他主题”多个平级入口。不知道全部历史时不显示“已整理100%”。

## 2. 新建主题与第一个窗口

新建主题只需要名称；图标/说明/Project策略可后设，不能要求先填目标、文件、十种标签。创建后得到稳定主题ID，即使0窗口也成立，显示本次“开始对话”上下文。关闭或刷新不删人工主题；不凭创建时刻伪造活跃段，固定或查找可再次进入。

已有单窗口可用主题菜单“从此对话建立主题”；预填标题仅候选，用户确认即可，引用仍在原Project。0/1/多窗口不决定是否值得保存。

卡头/侧栏主题的“＋”在hover、keyboard focus或触屏菜单可达，读屏名“在{主题名}中新建对话”。主题标题仍不承担折叠/新建两种混合功能。全站原生“新聊天”没有这个行为，不拦截原生按钮。

### 首次尚无目的地

点击主题“＋”显示一次轻量目的地选择，推荐主动作“在同名 ChatGPT 项目中开始”，其次为选择已有Project、仅归入主题。展示的是实际目标和语义，不是技术scope字段或长报告。

用户选同名项目后，可信确认面板说明名称、账户/组织、原生共享/记忆/工具约束，以及不会移动旧对话或替用户发送。同名候选不自行复用；选择现有项目使用稳定ID并核验权限。需要登录/权限时交给原生页面，扩展不处理密码。

创建成功后显示真实原生输入区；扩展不复制输入框，也不先接收首条正文。尚无真实conversationId时，仅维持当前待开始上下文。用户自行发送并由宿主保存，核验真实ID与Project后窗口加入主题。自动创建Project ≠ 自动发送聊天。

### 此后已有默认目的地

“＋”直接进入用户曾确认的目标Project的新聊天入口。目的地在原生Project头部/首次选择或主题菜单可查，不把来源行加回每个窗口。默认只因用户选择改变；浏览其他成员或另一个Project不会改默认。

若原生Project权限、共享/记忆/工具能力显著变化，或目标失效，显示简短选择，不静默转普通聊天、降级模型、创建第二个项目。重命名主题不级联重命名原生Project；可另提同步名称，属于独立操作。

## 3. 创建中的错误与取消

| 状态 | 用户看到/可做 | 不允许 |
|---|---|---|
| 未派发、用户取消 | 返回原工作区，保留空主题 | 标记已创建Project |
| 已派发、结果不明 | “结果尚未确认”，可打开原生项目核对或重新确认后处理 | 无提示重试创建、换tab重置预算 |
| Project成功，新聊天没打开 | 保留Project入口，继续打开相同Project | 自动删除Project或重复创建 |
| 原生聊天已保存，本地关联失败 | 保持原生聊天可用，重试本地归属 | 再发送或再开一个聊天替代 |
| 用户改了目标/账户 | 停止旧流程，保留其审计与已完成结果 | 将旧回包安到新主题/新账户 |
| 原生无能力/无权限 | 明确受限；允许用户选派生路径或在原生手动操作 | 把虚拟Project画成原生成功 |

当前输入、生成与原生工具状态优先。离开工作区不让pending请求自由继续写。恢复程序只展示已记录结果及待核对事项，不自动恢复执行授权。

## 4. 内容识别、单窗口与大量窗口

用户在主题里发起的窗口直接进入主题；AI可以发现偏题，但不能阻止或推翻该归属。用户人工提升单窗口为主题不需置信度阈值；系统自动发现的新主题可以只有一个窗口，但必须是清楚的独立工作对象/目标，不以每条对话自动生成卡片。

自动建议按需附于主题菜单/初次整理预览，不出现日常审批箱。点“为什么”显示实际记录的依据与缺失，不即时编一个事后理由。否决后保存针对本建议的约束，不重复烦扰；一个拒绝不自动推广到所有相似词。

窗口多且同目标：先查找、近期容量、系列、工作集；不会为了卡片变矮拆主题。目标分化时才建议拆分，预览成员分配、保留原ID的部分和新主题名。合并同样明确保留ID和冲突，不靠同名一键吞并。所有操作可按inverse安全撤销，原生Project/聊天不搬。

## 5. 自适应显示的入口与稳定性

**没有新常驻时间条。** 在既有工作空间设置里加入“显示范围”：自动、7/14/30/60/90天；这里允许文字和详细说明，日常卡片仍不显示日期或跨度。tooltip可解释上下是相邻较早/较近区间，不要求用户理解日历公式。

自动模式仅在证据充分时评估当前已知工作区密度；不足时维持原跨度。新安装从30起步，老用户保留固定30直到启用自动。人工选择固定H跨标签/重启保存，系统不改回自动。

只有在新进入工作区且无编辑/拖动/菜单/原生工作冲突时才应用pending跨度；既有历史会话与返回路径保留旧H/T/Z。另一tab更改设置不强制重排当前tab。手动改变H是明确操作：保留当前对象，按锚点重定位，不把旧k直接套进新跨度。

自动应用可有一次短暂“已调整显示范围 · 撤销”。撤销回旧H并保持固定，直到用户主动开自动。不通过动画将主题卡偷偷移到别处；减少动态设置继续生效。24主题在近7天均有新输入时照常显示，不用强制只显示前10个制造整洁。

## 6. 原生＋派生连续侧栏

沿用：上部原生标识/新聊天/原生搜索/真实dot，中部当前主题与其他活跃主题，下部原生Project/固定资源，底部原生账户。dot的用户头像/字体/状态直接保留，不受扩展单色图标规则影响。未知原生入口默认保留，低频功能沿用原生结构，不设静态白名单删掉。

点击窗口只切原生聊天，侧栏不消失。当前主题自动展开，其他主题默认折叠；用户主动展开和手动折叠分别记录，后台刷新不覆盖。一个对话多主题时优先使用用户点击/创建时明确的主题语境；直接原生打开没有明确语境则不按first-match假定唯一主题。

历史/未知当前窗口可临时出现在侧栏，属可达例外、不算活动。工作集与当前原生运行状态不随H改变而关闭。桌面开合由用户控制；窄屏抽屉可配置选中后收起，触控入口不依赖hover。

## 7. 聊天、返回、搜索和新建保持原生

ChatGPT继续持有真正的transcript、composer、model/tool菜单、附件/Canvas/语音、交互回复、原生动效、授权/错误和特殊页面。扩展CSS只作用自有根，不克隆或搬动这些组件，不吞并原生搜索结果或快捷键。

阅读区只有一个无字四格返回，位于经过验证不遮原生控件的位置；返回保存的主题段/工作集/展开/滚动。侧栏/折叠轨不新增重复返回；原生ChatGPT标志、浏览器Back/Forward、Cmd+K及项目上下文不改义。无安全空位先退回原生，不强行挤压。

派生查找仍与原生搜索分开：只搜已知标题/别名/主题/获准片段，不宣称全文/全账户。消息锚点须唯一branch/message及正文hash；无法确认时原生打开/查找，不滚动到一个看似相似但错误位置。

主题内新建目的地确认只发生在此明确入口，不挟持普通“新聊天”。原生Project内部工具限制与共享警示不得为简洁被删除。

## 8. 恢复、访问性与完成界线

受控退出仅撤自有节点/样式/属性，不刷新有草稿的页面；已经单独创建的原生Project不会因关闭VAIWL被删除。备份保留人工主题/归属/目的地偏好，恢复后原生引用待核验，native grant和待派发动作不恢复。

图标有读屏名称、键盘focus、实际命中区和可触控菜单；原生IME/生成不被新建或自动调H打断。任何无法访问的旧/未分类/未知对象均应在已知查找可见，不能只测试前五行。完整用例见[统一验收](research/V28_BASELINE_AND_ACCEPTANCE.md)。本轮无新原型或用户实验通过声明。
