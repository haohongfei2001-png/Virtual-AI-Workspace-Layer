# 信息架构、页面与关键交互规格

状态：PROPOSED；研究来源 §4–7、§10、§12、§20。原型实际行为另见 [逐项证据](research/PROTOTYPE_EVIDENCE.md)。文中的建议默认受 PD 决策约束；安全语义不因像素选择改变。

## 1. 导航结构

一级入口为新对话、搜索、当前工作集、少量常用工作区、全部已知对话、原生功能及设置/恢复。稳定工作区没有无限递归目录；工作区内可选分面建议 3–5 个，少量对话时不制造空分类。相关对话按需出现，优先明确前序/同任务/实际联用，不沿相似图无限扩散。

同一对话多重归属不产生多个原生实体。当前导航工作区不是对话唯一所有者；跨工作区跳转尽量保留用户来路，不用 memberships[0] 强行认定唯一语境。

## 2. 页面与状态

| 视图 | 内容与主动作 | 空/未知/失败处理 |
|---|---|---|
| 当前对话 | 轻量工作区/短标题、可查原生来源、系列/相关入口；中央原生聊天与输入 | 来源未知照实显示；不补造正文/摘要；不支持增强则原生继续 |
| 工作区概览 | 名称/范围、继续入口、现场、少量分面和密集列表 | 无对话可从已知列表加入；不虚构“最新”；少量项不强制卡片 |
| 当前工作集 | 有序引用、当前项、保存/恢复/移除 | 移除工作集不关闭原生 tab、不删除聊天；真实关闭动作另行清楚定义 |
| 搜索 | 工作区、原/派生/历史别名、获准已索引输入及片段 | 未找到不等于不存在；可转原生搜索，说明覆盖度 |
| 来源详情 | 原名、派生名、Project 观察、角色/范围/快照覆盖、依据 | 来源未知不能开放危险操作；历史快照不当作当前权限 |
| 显示改名 | 输入名称、原名参照、保存、人工保护、恢复自动 | 空名拒绝；并发冲突不静默覆盖；取消无写入 |
| 归属纠错 | 属于/不属于/同时显示/只在这里/恢复自动 | 明确仅派生；人工排除持续有效；可撤销 |
| 初次整理/导入 | 已知批次、来源范围、解析/去重报告、建议预览、批次撤销 | 账户不匹配/格式不明隔离；不能报全账户 100% |
| 原生改名审阅 | 另一个可信扩展界面，原名→新名、精确目标与次数 | 无授权、冲突或 UNKNOWN 不执行/不盲重试 |
| 设置/恢复 | 数据来源、权限、预算、备份恢复、诊断和原生入口 | 不变成日常管理后台；错误细节无私人正文 |

## 3. 首次启用与历史整理

在现有 ChatGPT 对话启用时停留原处；不加载管理首页，不改 URL、不发送消息、不抢输入焦点。先能用引用/标题，不强制付款、登录云模型或上传历史。页面观察、持久文本索引、云处理、原生改名、同步分开告知与授权。

无法核验宿主账户时，不展示旧 vault；保持原生，或提供完全独立的合成演示。用户选择 vault 不等于验证宿主账户。

旧聊天有三条路径：先用已知引用；用户提供官方导出；正常打开时逐步补全。导入在本地解析，显示已知数量、重复、未知字段、分支、Project 覆盖、拒绝项；一次批次组织可撤销。可通过少量代表样本纠正同批建议，不要求逐条审批，也不创建日常待处理收件箱。

## 4. 新对话

工作区中的新建必须能看见实际原生目的地：普通聊天或已核验 Project。目的地可能被记住，但必须可改且不改变历史对话所属。派生 PAIA 工作区不自动为新对话提供其他 Project 的文件/指令/记忆。

用户通过原生机制发送并形成稳定对话身份后，才可将获准用户输入作为证据；未发送草稿、IME 组合文本不持久采集。高精确率派生建议按批准策略应用；不确定项只是相关建议或保持原样。

原型的固定目的地下拉与假新聊天不证明任何 live 创建、身份或自动归类。见 PD-05。

## 5. 稳定命名与系列

全局名包含对象＋任务＋必要限定；工作区内部可去重前缀。中文长度以可区分性为先，6–18 汉字等效宽度只是研究建议，超出时省略显示但可查看完整名称，不截断保存内容。

人工改名后锁定；旧显示名称进入检索别名。未知原名作者不能假定为 AI；外部原名变化更新观察并暂停原生自动化。自动标题在稳定发送证据后形成，后续优先增补片段与别名；无新有效证据不重排、不改名。正在输入、拖动、定位一行或生成期间不换名称/顺序。

系列只用于明确继续/分支；相似话题不自动续号。对话序号与软件版本分开；整数元组 1.9 后为 1.10。首次看到旧历史不是新对话，不发新序号。删除旧项不重排，离线多设备无法保证唯一时暂不自动编号。

## 6. 纠错、拖动与撤销

拖入建议代表“也在这里显示”。原型实际先弹多选确认，而非直接落盘；最终交互见 PD-04。取消不变更；保存只改 Placement/人工约束。去掉原有位置形成持久 exclude；AI 后续不能加回。影响同系列/未来对话需另行明确，单个纠错不自动泛化。

撤销只撤本次派生操作，使用原 revision 的逆操作/冲突处理，不恢复整个旧快照覆盖后来修改。撤销名称不撤原生改名；删除工作区不删原生聊天。数据模型必须保留这一界线。

## 7. 搜索与片段

同一搜索入口覆盖已知工作区、标题、全部历史别名、获准输入及片段。当前工作优先但有全局逃生；结果带真实来源和覆盖，不为未读消息生成摘要。搜索快捷键不占用原生键位；Alt/Option+K 是原型选择，需平台键位验证与可改。

精确片段跳转需验证 message/branch 身份与当前渲染范围。只有文本指纹时验证唯一性，不能碰到第一个相似文本就跳；缺失回退原生对话/查找。局部片段主题不强迫主标题改变。

## 8. 多标签、现场与阅读连续性

Conversation 是一个；TabInstance 可以多个。单击优先聚焦已匹配范围的 tab 是建议（PD-02）；修饰键/中键新开与链接复制保持明确行为。仅 URL 相同不证明当前账户相同。

现场只保存引用、顺序、当前项、必要窗口关系及经过验证的阅读锚点；不默认保存草稿、正在生成回复、Agent 内部状态。恢复先呈现工作集/当前项，其余惰性打开；已有 tab 去重。失败项保留并说明，不像原型 filter 一样静默丢弃未知引用。去重不关闭用户其他窗口。

阅读锚点需要内容 revision/分支检查；失效时只回到对话，不夸称完整现场。人工固定顺序不被热度刷新覆盖。工作区概览开关不写入伪造的原生 history.state。

## 9. 原生切换与异常

受控切换只撤除扩展拥有的挂载和属性，不导航、不重发、不清空输入。原生 title 保持最近真实状态，派生 alias 隐去；单独执行过的原生改名不随开关回退。

页面适配失败时局部停止增强，原生可用；不得用“等待 AI 修复”遮住页面。禁用/卸载后清理 JS 不保证执行；原生刷新是逃生，不允许自动刷新正在工作页面。必须实测租约、冻结、后台节流、worker 死亡、更新和禁用链，不能用模拟 fault 按钮作证。

离线仍用获准本地组织/搜索；模型失败不清空既有数据。恢复授权只针对派生库，不重放旧云任务或原生写入。

## 10. 主题、键盘和无障碍

设计目标：原生输入可用优先于导航空间；窄屏先折叠派生导航；所有拖动有菜单等效；名称/来源/选中态可被读屏；modal 关闭恢复逻辑焦点；快捷键不打断 IME；200% 缩放不遮挡；普通正文对比目标 4.5:1；减少动态时无信息损失。

原型只有浅色、390px 布局与少量键盘断言，未完成这些全部目标。228/246px 侧栏、58px topbar、820/1100/1700px 响应点是原型观察值，不是生产 layout contract。模型、工具、附件、Canvas、语音、分享及未来原生入口只能根据实际能力保留，不能用静态“功能说明”代替可用入口。
