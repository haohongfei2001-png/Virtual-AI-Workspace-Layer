# VAIWL 交互规格：Free-first整合正文

范围：[Free/Pro合同](FREE_PRO_PRODUCT_SCOPE.md)。本页不再让Free先建虚拟主题、改派生标题或等待AI分组。沿用已批准v2.7视觉，原件不改；具体活动算法在[核心规范](CORE_MECHANISMS_V2_8.md)，本页只规定用户流程。

## 1. 主页和无项目聊天

真实Project一张卡，原生名称为标题，内部只列实际成员的原始聊天名。主页卡不整卡折叠；近期行5条预览/+12增量是现有视觉容量基线，不能截掉后续行；左侧小箭头只展开旧成员，不夹带未显示完的近期行。

无项目聊天是主页同等可操作的独立紧凑列表，不伪装成一个真实Project，不一聊一张大卡。没有Project时它直接成为主要内容，不等AI或项目初始化。当前H适用于其各条聊天；旧无项目聊天随相邻历史区间出现。无项目列表不作为单个主题计入自适应项目数量。

成员归属UNKNOWN与确认无项目分开；正常清单保留待核对的原始引用入口，避免丢失，只有详情/必要提示解释状态。活动完全未知不虚构日期；不长期loading，也不在主界面新增审批箱。权限未知则只保留真实原生可达入口，不展示旧scope的敏感标题。

默认使用原名。原生名称缺失时显示上次有效原名或明确占位；禁止拿Pro派生名、LLM概括或按路径猜名称补齐。两个同名原生Project不合并；通过原生上下文/就近详情区分，不在每行常驻来源或计数。

## 2. 活跃与历史的用户体验

新发送已确认后即时可见；新开但未发的composer只作为当前工作入口，退出或临时状态过期不永久激活父Project。仅访问旧聊天不会把它挪回最近。

若已知最后用户发送为60天前，在30天视图应立即按旧锚点进入较早区间，覆盖不够时内部是暂定，不为等全量证明无限置顶。后来发现手机新活动，后台更正到最近。未知的新鲜度/超时不能被当作“没有新消息”的事实；完全无日期的行保留稳定原生相对位置并有限校准。

Project只出现于一个显示段，旧聊天仍留父Project内；无项目聊天按自身日期分段。当前历史聊天、手工固定和工作集只是可达例外，不伪造活跃和重复卡片。重排须保存焦点/选区/当前项，用户操作期间可延迟视觉移动但不能无限延迟已确认变化。

上下图标保持：当前段只有向下，较早段才有向上；相邻区间长度一致，不暗跳空段。主页无日期、来源、计数或“自动·14天”常驻条。hover/focus/读屏名称说明行为，触屏入口不依赖hover。

## 3. 时间设置与现场稳定

在现有工作空间设置中选择固定7/14/30/60/90或自动；默认30，旧安装保留其设置。自动是Free非AI能力，资料不够就维持当前范围而不是禁用工作区。项目少但无项目窗口多，不凭项目计数武断拉长。

现有历史浏览固定H/T/Z/session；另一tab改偏好或跨午夜不会把原k重新解释为新跨度。用户明确改H时按当前对象/日期锚点定位，返回保持新的明确来路。自动变化只在安全进入时应用，短暂可撤销提示，不加永久时间导航栏。

## 4. 新Project与新聊天：真正原生动作

项目卡/侧栏项目“＋”打开该真实Project的新聊天入口，保留原生Project上下文及模型工具能力。没有真实保存ID时不能把占位窗口写成正式ConversationRef。用户使用原生composer自己发送，扩展不截获草稿另造输入框或代发第一句。

新Project入口打开原生创建流程，用户自己确认名称/共享/权限，后验观察到真实Project后才形成卡片。Free没有“先新虚拟主题，再无提示创建同名Project”的路径。入口不受支持时保留原生Projects可用路径并解释限制，不能画一个假成功项目。

全站原生新聊天保持原行为；原生搜索和快捷键仍打开原生搜索。Free不提供以改变虚拟Placement来冒充原生移动的拖动操作。原生改名/移入/移出在原生完成后反映到Free；无法核验结果时不自动重试或覆盖。

## 5. 连续侧栏与阅读返回

上方保留原生标识、新聊天、原生搜索、真实dot；中段为当前Project及其窗口、其他近期Project折叠标题，无项目入口及当前无项目聊天；下方原生资源/固定/账户继续原生。大列表不挤掉授权/运行/错误状态。

点击Project内聊天后，当前Project展开、其他默认折叠；手动开合是用户偏好，不因渲染刷新反复被重置。无项目聊天进入后不伪造所属Project；历史或未知当前项始终可访问。窄屏抽屉/桌面侧栏遵循已有用户选择。

阅读区只有一个无字四格返回，恢复工作区段、展开、容量、滚动和当前入口。原生标志/模型/浏览器Back/Forward不改义，侧栏和轨道不再重复入口。无安全挂载空间时收回扩展自身占位，不遮原生模型、工具、分享或输入区。

## 6. 原生功能和共享工具

消息/模型/工具/附件/语音/Canvas/图片/代码/交互回复/原生动效、权限和专用页由宿主自身拥有，不能通过复制相似UI伪称保留。未知原生入口默认可用，不靠固定白名单删掉。dot沿真实头像、名称、字体和状态，未获得素材不造形象。

Free可使用现有非AI工作集、手选片段、固定、备份和恢复；它们不变成虚拟主题或改写原名。已知查找只搜索原生名/可靠旧原生别名/手选片段，清楚说明覆盖；不会索引Pro派生名来间接显示收费语义。原生搜索仍覆盖其自身实际能力，不被局部索引替代。

片段精确跳转仍需唯一message/branch和有效bodyHash；失配回原生对话/查找，不跳到相似文本冒充成功。Free不因Pro开关关闭而丢掉共享人工作品或恢复功能。

## 7. Pro附加流程（后续）

Pro在Free界面上增加独立虚拟主题/派生名模式，首先组织确认无Project聊天；剩余行按原名仍可达。真实Project与VirtualTopic不共用ID或暗中合并。用户可以回原始Free视图验证原始结构。

人工更改虚拟名/归属、lock/exclude、拆合/系列全部保留为Pro能力；拆合要有目标和冲突预览，不以窗口数量硬拆。虚拟主题“开始工作”选择原生目的地的复杂路线及代理原生操作属于Pro/E后续，不插入Free正常新建流程。

AI自动执行只限经过批准并验证质量的可逆派生操作；从shadow/预览到自动不要求用户永远逐条维护，也不能绕人工约束。模型不可用立即回原始入口，不阻塞Free新聊天、阅读、历史和搜索。

## 8. 完整验收而不是只看图

C5/C6必须验证键盘/200%/物理IME/深浅/窄屏/弹层避让、操作焦点、实时生成、项目更名/成员变化、无项目长列表及退出。受控关闭、实际disable/freeze、原生可用、布局干净、数据保全分别记录。不自动刷新有草稿页面换取“恢复成功”。本轮只整合规格，没有这些新场景的PASS。
