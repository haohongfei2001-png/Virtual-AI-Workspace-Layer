## 1. 三类对象不混淆

FreeProjectCard对应同scope的真实NativeProjectRef；项目ID不是标题。FreeConversationRow显示真实nativeTitle。无项目聊天定义为经过来源核验的NONE，不是没有读到projectId；UNKNOWN归属另有可达行，不能混为NONE。Pro VirtualTopic/VirtualPlacement/DerivedTitle独立于上述事实：它们只改变Pro展示，不是原生成员关系。

Free不读取旧虚拟主题成员来构造卡片，不从旧identities选择标题，不因手工MOVE改变实际Project。用户在原生端改名/移入/移出，经可靠观察更新原生事实；同名两个Project独立。没有项目的账户直接显示普通聊天，不空着首页等待主题。零聊天Project仍是原生对象，在当前创建上下文、原生Projects或已知查找可达，不编造活跃。

全部已知且获准引用至少有一个可达入口：Project卡、无项目列表、归属待核对行、当前上下文或已知查找。未知账号不能通过可用性原则显示其他scope资料；保留真实原生UI而不是猜账户。浏览器DocumentBinding只证明当前文档，principal/context的ScopeGrant独立核验；页面字段、nonce和来源名称不能自证授权。

无ID/href的实际原生Project按钮可由文档内LiveNativeHandle表示并让用户原生激活一次；renderKey不是nativeID。正常路由/加载metadata取得exactID后提升为正式P，不按名字/行号合并或重找重建节点。候选阶段不阻塞原生访问，也不能被永久当成完整映射；完整profile必须包含可靠身份、NONE和活动来源的正常成功闭环。

## 2. 原生新建与不变的界面

沿用批准v2.7的卡片/紧凑行、主页不整卡折叠、侧栏当前项目展开、用户控制侧栏、旧窗口左侧展开、右缘上下区间、阅读区一个无字四格返回。无常驻日期/来源/计数/“自动14天”标记；必要的原生账户/Project/权限提示不能删。四格返回不因header不足改为侧栏/rail重复入口。

Free项目“＋”进入已核验原生Project的新聊天入口；新Project打开原生创建流程，由用户决定/提交，核验真实结果后才出现卡片。没有真实ID的composer不是已保存聊天；当前空白会话可以临时可达但不制造发送。全站新聊和P内新聊目的地显式区分；无当前P内入口先P导航，用户继续原生流程，不后台多步创建。

全站原生新聊天/搜索/模型/工具/附件/消息/IME/Canvas/语音/交互回复和未知入口保持原生所有权。关闭VAIWL不删除或撤销用户在原生完成的操作。自动代理建Project、改名、移动属于独立E，不是Free完成条件或订阅默认权限。

生产采用同一个MountSurface下的manual workspace/sidebar surface及扩展origin UI frame，复用现有renderer和共享ViewSession/索引。只对经过证明的独立reading和纯history列表施加由`:popover-open`决定的最小CSS visibility/interactivity视图mask；不得写原生HTML inert/hidden/display、移动原生DOM或mask composer/模型/工具/文件/账户。声明式关闭释放对应mask，原生弹层优先，完整v2.7不降为小弹板。原生全历史/搜索/目录继续可达；实际disable/uninstall的敏感残留与原生可操作性分别验，不能仅凭可手关判通过。具体边界依1.1主规格§7，不另设挂载方案。

## 3. 活跃准确与不断档：两个层次，一套确定决策

### 3.1 不可伪造的原始事实与分层观察

原始UserSendEvent只有经核验的作者/角色、真实对话/消息/分支或固定到消息的可核验谱系、已提交新发送及原始时间才成立。精度为日期/范围时保留区间，不补成当天00:00的精确消息时间。共享项目role=user、拥有会话、MAIN自报作者不自动等于本账户本人。

ObservationHint保留原有来源提示与短期有效期。新增的LocalSendAnchor属于同evidence体系中的`observed-self-send`持久观察锚：只有本地本人intent、确切message/operation和独立确证ACK关联后才能建立，保存首次本机有界观察区间/ACK witness/clockBasis/calibrationDueAt，始终只支持provisional，没有sentAt/serverTime。它不是放松UserSendEvent，也不能由旧短TTL hint批量升级。

点击、打开、改名、改文件、AI回复、updated_at、HTTP Date、导入、首次发现均不自动算新发送。合格的同域原生近期顺序可供无日期排序；经核验语义/单位的对象更新时间可供provisional最近活动。二者不写本人sentAt、actorVerified或成功ACK；首次观察只建baseline，轮询/置顶/筛选/虚拟滚动不续发送或原生更新时间；用户明确打开并确认到达可更新独立本地最近使用，不续写任何发送锚。严格UserSendEvent与ACK锚原义保留，UNKNOWN不作NONE，未见不删除，原生搜索始终可达。某种字段用作弱提示也需验证负面语义；没有合格ACK、只有optimistic气泡或整个流complete不得形成持久观察锚。

同scope/C/message语义事件只记录一次，重复打开不修改immutable事件的observedAt，lastSeen/witness另行更新；event key不得依赖current branch leaf，谱系固定到该消息。相同message原始时间冲突隔离，不取较晚值。InventoryCoverage、成员完整性和TimeCoverage分别保存：已读一些对象不等于全账户；一条可信今天发送可证明近期，却不能证明历史无更晚输入。NONE按各自活动计算，不把整份普通聊天列表造为一个Project。

### 3.2 显示决策（不写回原始事实）

ActivityDecision包含对象ID、exact/interval/provisional/undated依据、可选candidateDay、segment、证据版本/有效期、理由和下一核验点。所有已知记录先按可用事实渲染，慢来源异步校准；决策不改原生归属/发送事实。

| 输入情形 | 即时决定 | 之后如何退出或校正 |
|---|---|---|
| 当前窗口有无冲突的本人近期原始新发送 | 最近，按有效原始时间/精度排序 | 更强来源补证；重复重开不产生第二事件 |
| 本地本人发送ACK已确证但原始时间未证实 | 用durable观察锚暂定recent，保持本机观察区间和provisional | calibrationDueAt仅催核验，不能抹已ACK活动；新证据可提升或撤销，不转存观察时间为sentAt |
| 已知最后发送日期为60天前，H30，后来覆盖不完整且无更新正向线索 | 暂定较早，按历史锚进入对应段，不为等全量证明无限留最近 | 来源新活动到达即提升，明确暂定，不宣称证明从未再发 |
| 所有成员均有足够排除更晚发送的覆盖 | 证实较早，按最近真实发送分段 | 新发送/成员变化/覆盖失效重新核对 |
| 一个成员的时间或内容互相矛盾 | 不挑有利时间冒充准确，保留可逆位置/原生排序 | 优先核验矛盾来源，已证正向事件不被无关unknown抹掉 |
| 刚打开空新聊天，尚未发送 | 仅当前工作现场临时可达 | 关闭/取消/临时期限解除置顶，不使父P永久活跃 |
| 完全无可用时间或近期线索 | 不编造日期，原生稳定顺序与现有列表可达 | 有限校准后结束spinner，不因超时断言不活跃 |

完全未知对象不进入必须人工逐条审批的队列；在原始列表/项目视图非置顶位置保留入口，既有查找可达，详情解释依据，必要时一处非阻断受限提示。它不计已证活跃数，不能据此声称准确分段完成。主要真实数据长期未知时FREE-DATA未通过，界面可用不替代来源能力。

**过期类别分开**：旧短期hint失效后，才按仍有效的旧日期暂定较早或无日期回退；durable已ACK观察锚不因校准due失效，自然随H/T/Z变老，错误关联/失败或来源撤销才撤销。grant过期先停止敏感显示，与事件时间/row freshness分开。轮询/重启/新鲜度更新不得续写任何活动锚起点。本机时钟异常不能形成可信日期区间时，保持当前导航/无日期并校准，不伪造原始时间。

临时新聊初始工程上限10分钟，仅第一次创建开始计时，刷新不重置；这项临时可达规则不同于已确证ACK的持久观察锚。正在使用的原生composer仍保持当前可达，不作为活跃事实。

### 3.3 项目、子窗口与排序

项目决策聚合实际成员最近有效可信活动（严格发送或provisional原生更新时间；相对顺序无日期），一个近期成员足以使项目近期。P有未知成员时不宣称完整历史，但已有旧锚可支持可逆下沉。P在一个显示段出现一次，子窗口跟随父项目；旧窗口在该P内展开，不按自身旧日期另造卡片。成员集合版本是P局部版本，无关Q更新不得使全部P成员失效。

NONE按自身活动分段；UNKNOWN独立可达，不假装Project。普通按有效活动排序，同值用原生稳定顺序/稳定ID；人工固定仅快捷可达，不把访问当发送。独立local-recent-use可由明确用户操作及当前对象确认形成provisional最近使用，首次发现/自动刷新/恢复/重复派发不产生使用。点选/拖动/composition时保持原目标、焦点和当前项，在安全更新点重排，不无限不刷新。历史ViewSession不会因另一个tab新策略改变而被重新解释。

### 3.4 校准调度与验收目标

优先级：确证本机新发送/账户变化/当前项→最近P/NONE新项→临界过期/弱证据→历史深层。继续既有FreeRuntimeService/FreeCalibration和同scope跨tab foreground优先，不建第二调度器。单请求6秒、轮次30秒/12请求、最多2次重试，取消/去重/预算跨lease、worker重连和多tab保持；权限peek不联网，refresh单飞。无源立即有限结束，不每次续lease重新发12次请求。

前台恢复、打开工作区、原生SPA/列表/当前数据修订和来源撤销触发必要校准；不后台大规模开页，不要求每日导出/补ZIP/维护日期。上游手机新活动先在desktop native实际可见才能自动吸收；语义已核验的updated_at可作暂定活动，未核验字段仍只dirty，不能伪本人时间。

以下为工程目标而非已测成绩：缓存投影满足原F1导航p95；本地合格新发送证据到达后1秒内更新可达显示，受支持源返回可信变化后1秒投影；前台30秒内完成首轮或明确降级。另行报告用户发送→合格ACK/时间证据、远端→桌面可见与本地处理延迟，不能将昂贵核验藏出统计。大历史发现分批更慢但要说明范围/结束条件。

F/R0本人日用先验原J1–J4个人连续路径；真实60天旧样本和另一客户端完整组合保留②/③，不是本人安装前置；未知例外可有限降级，典型主流程持续错分、漏列或不收敛不能宣布完整Free。81项/J1–J4及固定G/U见FR矩阵。

## 4. Free的时间范围与自适应

H∈{7,14,30,60,90}，默认30。当地日期T、IANA时区Z固定为ViewSession；W(k)=[T+1−H(k+1), T+1−Hk)。按当地日期而非H×24小时，历史上下连续、默认无向上，不暗跳空段。H/T/Z/policyRevision覆盖卡片、子行、未归Project列表和缓存。

人工固定优先；自适应属于Free非AI能力，而非Pro门槛。本人首版默认30和手动；以下自动H算法保留后续③，不以渐进目录或provisional伪造完整密度。统计不同真实Project ID，不统计窗口、虚拟主题、快捷固定或临时新聊。无Project占主体且项目计数不足以代表拥挤程度时，不用“项目很少”自动拉长；维持当前H，普通聊天仍按H显示。后续可研究独立列表密度但不得凭空把聊天聚成Free主题。

保留P28-A为可调整的工程初始策略：舒适带5–10，loss(n)=2·max(0,n−10)+max(0,5−n)，比较实际N(H)而非月活线性乘算。取最小loss的候选，平局先保留当前H，否则取与当前H的abs(log(H/Hcurrent))最近者，再平局取接近30者。正常变更需要oldLoss−newLoss至少为max(2,0.25×oldLoss)；当前为空而候选带回至少一项时门槛为1。所有候选同样稀疏/拥挤则保留H，不强制只显示10张卡。缺失范围可能改变最优结果时保持当前H；手动选择不受此门槛阻止。

最多每7个当地日评估，连续两次同向建议且最短驻留14日后，在下次安全进入工作区时应用；大导入/原生项目搬移/数据撤权后冷却。新安装auto起步30但无证据不自动改；旧安装保持legacy fixed30，直到用户开启auto。设置里可看范围，主界面不新增时间条；一次短暂可撤销变化提示即可。撤销恢复固定值。历史浏览与另一个tab的参数不被后台更改；手动换H按对象/日期锚点重定位，不复用旧k。

## 5. Pro保留为后续语义层

Free工程验收后按后续范围推进：对确认NONE的对话生成VirtualTopic及DerivedTitle，剩余未分类对话仍显示原名；AI失败、预算用尽或关闭不能丢窗口。人工include/exclude/lock/更名/撤销优先。单个窗口可以形成虚拟主题，空虚拟主题是人工资产，不是原生空Project。

保留原对象/目标识别、Series、工作集关联、显式跨Project引用和拆合；跨Project投影仅Pro额外模式，真实Project卡和原生成员不被重写。拆合根据工作目标分化，不按窗口数；保留ID/redirect/别名/负约束与安全inverse，不移动原生对话。

升级只增加overlay；降级立即恢复Free原名/原生Project与无项目列表，同时保留受scope保护的旧Pro人工作品供安全备份和将来恢复。真实数据引用重验、数据授权与模型权限独立。Pro订阅不授予ChatGPT原生写权；会员/计费不成为Free启动依赖。
