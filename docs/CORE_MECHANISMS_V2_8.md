# VAIWL 核心机制：Free原生工作区与Pro语义覆盖层

2026-10-13正文整合。此文件是当前机制Canonical，产品分级和Free优先由用户明确；旧v2.8“所有主题先是独立Workspace”的默认已经替换，不靠顶端注释覆盖正文。工程仍未因此实现，历史设计和测试见[基线表](research/V28_BASELINE_AND_ACCEPTANCE.md)，执行只遵循[唯一计划](DEVELOPMENT_PLAN.md)。

## 1. 三类对象不混淆

FreeProjectCard对应同scope的真实NativeProjectRef；项目ID不是标题。FreeConversationRow显示真实nativeTitle。无项目聊天定义为经过来源核验的NONE，不是没有读到projectId；UNKNOWN归属另有可达行，不能混为NONE。Pro VirtualTopic/VirtualPlacement/DerivedTitle独立于上述事实：它们只改变Pro展示，不是原生成员关系。

Free不读取旧虚拟主题成员来构造卡片，不从旧identities选择标题，不因手工MOVE改变实际Project。用户在原生端改名/移入/移出，经可靠观察更新原生事实；同名两个Project独立。没有项目的账户直接显示普通聊天，不空着首页等待主题。零聊天Project仍是原生对象，在当前创建上下文、原生Projects或已知查找可达，不编造活跃。

所有已知且获准引用至少有一个可达入口：Project卡、无项目列表、归属待核对行、当前上下文或已知查找。未知账号不能通过可用性原则显示其他scope资料；这时保留真实原生UI并等待身份，而不是猜测账户。

## 2. 原生新建与不变的界面

沿用批准v2.7的卡片/紧凑行、主页不整卡折叠、侧栏当前项目展开、用户控制侧栏、旧窗口左侧展开、右缘上下区间、阅读区一个无字返回。无常驻日期/来源/计数/“自动14天”标记；必要的原生账户/Project/权限提示不能删。

Free的项目“＋”进入这个已核验原生Project的新聊天入口；新Project操作打开原生创建流程，由用户决定/提交，核验真实结果后再出现卡片。没有真实ID的composer不是已保存聊天；当前空白会话可以暂时可达但不制造发送。

全站原生新聊天/搜索/模型/工具/附件/消息/IME/Canvas/语音/交互回复和新入口均原生所有权。关闭VAIWL不删除或撤销用户在原生完成的操作。自动代理建Project、改名、移动属于独立E动作，不是Free完成条件或订阅默认权限。

## 3. 活跃准确与不断档：两个层次，一套确定决策

### 3.1 不可改变的事实层

原始UserSendEvent只有经核验的作者/角色、真实对话/消息/分支、已提交新发送及原始时间才成立。精度为日期/范围时保留区间，不能补成当天00:00的精确消息时间。共享项目的role=user不自动等于本账户本人。

ObservationHint保存有来源的原生活动提示，或当前用户确已完成一次发送的本机观察；observedAt是观察时间，不冒充原始sentAt。点击、打开、重命名、改文件、AI回复、updated_at、导入、首次发现均不自动算新发送。对某种原生活动字段要先用负面场景验证其语义，才能作为弱提示。

InventoryCoverage、成员完整性和TimeCoverage分别保存：已读若干Project/聊天不等于全账户；一条可信今天发送足以证明当前活跃，但不能证明历史没有更晚发送。无项目聊天的活动独立计算，不能把整个无项目列表当一个最近Project。

### 3.2 显示决策（与原始证据数据库分离）

ActivityDecision包含对象ID、exact/interval/provisional/undated依据、可选candidateDay、segment、证据版本/有效期、理由和下一核验点。所有已知记录先按可用事实渲染，慢来源异步校准；决策不改原生归属/发送事实。

| 输入情形 | 即时决定 | 之后如何退出或校正 |
|---|---|---|
| 当前窗口有无冲突的本人近期新发送 | 最近；按有效原始时间排序，原始时间未核实则临时recent hint | 更强来源到达后替换依据；不能把观察时间转存sentAt |
| 已知最后发送日期为60天前，H=30，后来覆盖不完整且没有更新正向线索 | 暂定较早，按该历史活动锚点进入相应段；不能为等全量证明无限留最近 | 来源新活动到达即提升；详情明确暂定，不宣称证明“从未再发” |
| 所有成员均有足够排除更晚发送的覆盖 | 证实较早，按最近真实发送分段 | 新发送/成员变化/覆盖失效触发同一投影重新核对 |
| 一个成员的更新时间或内容互相矛盾 | 不选择有利时间冒充准确；保留可逆上次位置/原生排序 | 优先校验矛盾来源，已证正向事件不得被无关unknown抹掉 |
| 刚打开空新聊天，尚未发送 | 仅当前工作现场临时可达 | 关闭/取消/达到临时期限后解除置顶，不使父Project永久活跃 |
| 完全没有可用时间或近期线索 | 不编造日期；保留原生稳定顺序的未定年代表现和现有列表可达性 | 停止无限spinner并后台有限重查；不能因超时就断言“不活跃” |

完全未知的对象不进入一个必须人工逐条审批的队列；在当前原始列表/项目视图的非置顶位置保留入口，并可用既有查找抵达，详情解释依据，必要时只显示一处非阻断的数据受限提示。它不计入“已证活跃数”，不能借此声称完成了准确历史分段。**若主要真实数据长期完全未知，FREE-DATA未通过；界面可用不替代时间能力已解决。**

过期只使提示失效，不制造“最后发言日期”。新鲜度更新/首次访问/轮询/重启不得续写活动锚点。若提示失效后仍有旧可信日期，回到该日期的暂定较早；没有日期则undated保留，不偷偷猜一个历史月。临时新聊初始工程上限10分钟，仅第一次创建开始计时，刷新不重置；正在使用的原生composer仍保持当前可达，不作为活跃事实。

### 3.3 项目、子窗口与排序

项目决策聚合其实际成员的最近有效本人活动；一个近期成员足以让项目近期。Project有未知成员时不宣称完整历史，但已有旧锚点可支持可逆下沉。项目在一个显示段出现一次，子窗口始终跟随父项目；旧窗口在该项目内展开，不按其自身老日期另造项目卡。

无项目聊天按各自活动直接分段；归属待核对记录独立可达，不假装一个Project。普通按有效活动新旧排序，同值用原生稳定顺序/稳定ID；人工固定仅快捷可达，不把访问当活动。用户正在点选/拖动/输入/阅读时保存焦点和当前项，只在安全更新点重排，不能无限不刷新。

### 3.4 校准调度与验收目标

优先级：真实本机新发送/账户变化/当前项 → 最近Project/无项目新项 → 临界过期/弱证据 → 历史深层。请求可取消、去重、有预算；继承6秒请求边界，单周期同对象初始最多2次重试，失败结束等待并留下下一次触发条件，不阻塞其他对象。前台恢复、用户打开工作区、原生源修订与来源撤权均触发必要校准；不要求用户每天导出/补ZIP/维护日期。

以下为工程验收目标而非已测成绩：缓存到位后的投影仍满足原F1导航p95目标；本地确认新发送后1秒内更新可达显示；受支持在线源返回可信变化后1秒内完成投影更新；重新进入前台后30秒内完成第一轮有界校准或明确降级结束等待。大历史发现可以分批更慢，必须报告完成范围与结束条件。源本身尚未反映手机新消息时不能用本地重试伪装已收敛；记录上游延迟与本地延迟各自数值。

F/R0必须在有明确真值的干净数据集测“60天旧项”和“手机刚新增”反例。未知例外允许有限降级，但典型主流程持续错分、漏列或永不收敛时不能宣布完整Free。

## 4. Free的时间范围与自适应

H∈{7,14,30,60,90}，默认30。当地日期T、IANA时区Z固定为ViewSession；W(k)=[T+1−H(k+1), T+1−Hk)。按当地日期而非H×24小时，历史上下连续、默认无向上，不暗跳空段。H/T/Z/policyRevision覆盖卡片、子行、未归Project列表和缓存。

人工固定优先；自适应属于Free非AI能力，而非Pro门槛。先实现固定与手动，再在有充分库存/活动证据的已知Project总体上选择H。统计不同真实Project ID，不统计窗口、虚拟主题、快捷固定或临时新聊。无Project占主体且项目计数不足以代表拥挤程度时，不用“项目很少”自动拉长；维持当前H，普通聊天仍按H显示。后续可研究独立列表密度但不得凭空把聊天聚成Free主题。

保留P28-A为可调整的工程初始策略：舒适带5–10，loss(n)=2·max(0,n−10)+max(0,5−n)，比较实际N(H)而非月活线性乘算。取最小loss的候选，平局先保留当前H，否则取与当前H的abs(log(H/Hcurrent))最近者，再平局取接近30者。正常变更需要oldLoss−newLoss至少为max(2,0.25×oldLoss)；当前为空而候选带回至少一项时门槛为1。所有候选同样稀疏/拥挤则保留H，不强制只显示10张卡。缺失范围可能改变最优结果时保持当前H；手动选择不受此门槛阻止。

最多每7个当地日评估，连续两次同向建议且最短驻留14日后，在下次安全进入工作区时应用；大导入/原生项目搬移/数据撤权后冷却。新安装auto起步30但无证据不自动改；旧安装保持legacy fixed30，直到用户开启auto。设置里可看范围，主界面不新增时间条；一次短暂可撤销变化提示即可。撤销恢复固定值。历史浏览与另一个tab的参数不被后台更改；手动换H按对象/日期锚点重定位，不复用旧k。

## 5. Pro保留为后续语义层

Free工程验收后按后续范围推进：对确认NONE的对话生成VirtualTopic及DerivedTitle，剩余未分类对话仍显示原名；AI失败、预算用尽或关闭不能丢窗口。人工include/exclude/lock/更名/撤销优先。单个窗口可以形成虚拟主题，空虚拟主题是人工资产，不是原生空Project。

保留原对象/目标识别、Series、工作集关联、显式跨Project引用和拆合；跨Project投影仅Pro额外模式，真实Project卡和原生成员不被重写。拆合根据工作目标分化，不按窗口数；保留ID/redirect/别名/负约束与安全inverse，不移动原生对话。

升级只增加overlay；降级立即恢复Free原名/原生Project与无项目列表，同时保留受scope保护的旧Pro人工作品供安全备份和将来恢复。真实数据引用重验、数据授权与模型权限独立。Pro订阅不授予ChatGPT原生写权；会员/计费不成为Free启动依赖。

## 6. 完成界线

本规范确定的是应实现的规则。Free完整交付需原生Project/无项目发现、实际活动、原生保留、恢复和受支持的跨设备再发现都有真实验收，见[FR矩阵](research/FREE_PRO_ACCEPTANCE.md)。现有代码/合成测试未自动升级成这些能力。既有自动创建Project的复杂计划留在独立E/Pro储备，不恢复为Free默认流程。
