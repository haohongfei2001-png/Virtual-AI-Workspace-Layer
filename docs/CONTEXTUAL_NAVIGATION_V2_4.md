# VAIWL v2.4：连续主题导航、克制图标与统一展开

2026-10-10。基于 Draft PR #1 / `1f2330fab1b6f28006cf46db21f0444608394297` 和实际 v2.3 原型的定向增量。不是重新研究，不实施正式扩展。时间事实、唯一主题分段、原生 Project/消息/权限和人工优先边界仍以 v2.1 为准。

## 1. 本轮要求与解法

用户要求：不同主题可以有低调的不同图标；解释并解决卡片三个展开入口的混淆；进入正常聊天后保留可由用户控制的主题侧栏；当前主题展开、其他活跃主题默认只显示主题名，非活跃主题不常驻；检查首页“以前/其他主题”的重叠。

明确要求是持续的主题导航、用户控制展开/收起、不牺牲原生聊天。图标的具体语义、5行首页预览、8行侧栏预览、“全部对话/全部主题”用词和未知记录的次级位置为本轮可评审解法，不自动升级为全部获批。当前视觉基础沿用 v2.3；不重新引入日期、来源、计数或独立品牌色。

## 2. 原型原有三个入口为什么令人困惑

| v2.3 入口 | 原来实际含义 | v2.4 处理 |
|---|---|---|
| 展开窗口 | 活跃窗口超过默认三行，展开尚未显示的活跃窗口 | 日常样本直接显示至多5个；不再把预览截断包装成分类 |
| 以前的对话 | 已有证据确认不在父主题最近活跃段的旧窗口 | 仍折叠，但从中性“全部对话”进入 |
| 其他对话 | 时间缺失/覆盖不完整，无法可靠判定的窗口 | 不作为第三个常驻入口，也不改判为旧窗口；中性“全部对话”保留访问 |

三个入口不代表三个真实工作类型。前一个是显示容量，后两个是时间证据状态；平级摆放把内部实现暴露为用户必须理解的分类体系。

首页卡片默认列出至多5个近期窗口；多数日常主题无需任何预览展开。需要看剩余内容时仅一个“全部对话”入口：先补齐没显示的近期窗口，再呈现其余已保存窗口。展开内采用“继续显示”逐批到达集合末尾；这是容量控制，不是第四个分类。点击“收起”恢复近期预览。只有一个窗口且无隐藏内容时不显示空入口。

“全部对话”不是“全部旧对话”，不会把未知时间判成历史。当前原型沿用所有数据：日常 PAIA 有5个近期、2个旧、1个未知窗口；压力 PAIA 的60个成员均能抵达，没有按日期拆散父主题。默认不显示旧/未知记录，打开它们不制造活跃时间。

## 3. 主题图标：可辨识但不抢主内容

使用有限的同一单色线性图标家族：PAIA集合、论文研究、秋招公文包、输入法键盘、阅读书页、写作笔尖等。相同视口尺寸、描边、明暗和容器，不用随机彩色 emoji、不用夸张插画、不套品牌徽章，不要求每个主题有全球唯一图标。

图标在主题首页和聊天侧栏一致。原型用静态合成主题及小词典演示初次选择，不宣称模型已经准确推断。首次选择后按稳定主题ID保存；改名、时间翻页、模型重算不应自动换图标。模糊主题用中性集合图标，用户可通过主题菜单更换，人工选择优先。图标变更可撤销，不改变时间、归属、正文或原生标题。

继承主题头区/边界、一级从属线和对话符号；图标只是额外辨识线索，不代替标题，不以颜色作为唯一编码。

## 4. 一套主题数据，两种工作形态

首页用于扫描多个主题；聊天页用于继续当前工作。点击窗口后中央进入原生聊天，卡片区退场，但同一批主题以紧凑折叠树留在侧栏，不再只留下“返回主题”按钮。

例：点击 PAIA 开发1.0后，默认导航顺序为：

```text
新聊天
搜索聊天
dot

PAIA  [展开]
  开发1.0  [当前窗口]
  输入板交互
  官网文案
  命名规则
  同步边界
  全部对话  [折叠，含旧/未知窗口]
硕士论文  [折叠]
秋招      [折叠]
输入法    [折叠]
阅读      [折叠]
写作      [折叠]
```

底部集中返回主题、全部主题、工作集、回到原生与VAIWL设置/第三方身份；不在中央重新添加一条工作集工具栏。

### 4.1 进入、展开和定位

当前主题在本次进入聊天时置于侧栏前列并展开，当前窗口突出选中。其他近期活跃主题初始只显示主题头；用户点开主题头只展开列表，不导航、不发送、不抢占正在输入的对话。点击窗口才切换原生对话。

自动展开和人工展开分别记录：切换主题可收起上一个仅因当前上下文自动展开的主题；用户主动展开的其他主题保持展开。用户主动折叠当前主题后，不因失焦、时间刷新或重新渲染立即打开。下一次明确进入该主题的某个窗口时可再次定位目标，不能每次后台更新都重置状态。

首页卡片与聊天侧栏折叠状态分别保存，不将首页展开所有卡片变成聊天页展开所有主题。窗口/主题身份、派生标题、图标和归属只有一份数据。侧栏不是另一套可写主题数据库。

### 4.2 用户控制侧栏

桌面侧栏展开/收起由用户决定，跨窗口切换保持选择；进入聊天不自动隐藏，也不强制重新打开。折叠后保留窄导航轨，可以再次展开或直接返回原生。

窄屏用抽屉避免压缩原生输入区。候选默认选中窗口后关闭遮罩，但设置可关闭此行为；它不改变桌面选择。导航自身滚动，顶部主要入口与底部退出始终可达。低优先级功能不挤到当前窗口前面。

### 4.3 长主题与当前历史窗口

首页候选预览5行，侧栏候选显示8个近期窗口。超出时在近期列表尾显示“更多近期对话”；旧/未知记录仍由后面的“全部对话”统一揭示，两个动作在层级和文字上区分，不再有三个模糊并列按钮。全部已保存列表按12条继续显示，直到末尾；数字是实现容量，不展示为计数。

当前窗口即使超出预览也必须可见，不能要求用户翻页寻找已经打开的目标。用户打开活跃主题中的旧窗口时，保持该父主题，并展开包含当前项的完整列表；原活动时间不变。用户从历史/搜索/固定打开一个历史主题时，只将这个正在使用的主题作为侧栏临时上下文带入，其他历史主题仍隐藏。换到别的主题后这个例外撤除，不加入当前时间段，也不产生另一张月卡。

未知主题/未归类窗口被直接打开时同样可继续工作，不伪造时间或归属。多重Placement优先采用点击行携带的父主题，再用仍有效的最近访问语境；全局入口若没有唯一上下文则保留独立当前入口，不靠 `memberships[0]` 声称唯一归属。

### 4.4 dot 与其他原生功能

本次按用户指定顺序示意保留 dot。它不是VAIWL新造的机器人或复制聊天；原型点击只给未连接说明。正式扩展仅保留当前账户真实存在且已验证的原生入口，入口名称/链接来自宿主；不可用时不能画出假可用按钮，也不承诺所有账户都有 dot。其余原生模型、工具、Project和账户能力仍需保留，并按已批准的适配边界进入R0验证。

## 5. 首页“以前”和“其他主题”应如何整理

原来的两组数据不相同：“以前”是有可靠时间的历史主题，“其他主题”是时间未知/未归类材料。但两者承担相同的用户任务——找回默认主页之外的东西；并列放在首页让用户猜测该点哪个。

候选把首页收敛为一个“全部主题”入口。集合页包含三种可达内容：最近主题、按原有互斥日历段浏览的以前主题，以及一个次级折叠“未分期”。进入后近期组默认折叠，首先可看上一段，较近/更早负责按段浏览；未分期只有主动展开时说明暂时无法判断时间，不需要审批或每天维护。搜索的“包含以前的对话”同时涵盖未知记录，查找不等于激活。

“全部主题”必须真的能找到当前、历史和未知集合，不只是历史页面改名。各集合仍互斥：当前PAIA不再出现在以前组；未知集合不被塞到最老月份。首页不再单独常驻“其他主题”，也不静默丢弃那些记录。选择全部历史时仍可完整列出全部已知主题，不把主题总数当作账户全量统计。

## 6. 状态、数据与工程依赖

增加的都是派生UI状态：`accessTopicId`、自动上下文、人工 `navExpanded`、`navFull`、各视图预览位置、`sidebarPreference`、小屏抽屉偏好、`topicIcon`及人工owner。不改原生Project，图标/固定/展开/访问不写发送事件。

侧栏最新活跃集合独立于用户正在浏览的历史段；“全部历史”不是把所有历史主题永久塞进聊天侧栏。当前访问例外与活跃投影分别建模。切换账户清除旧上下文、展开和迟到结果，不能沿用A账户当前项到B；正式持久偏好须限定scope和设备，不携带原生写入授权。

C1/C2首次交付应同时覆盖首页与聊天侧栏共享主题、独立展开状态、用户控制侧栏、图标稳定性、统一入口和当前例外，不推迟到C5后期修补。C3保留工作集而不恢复中央多余工具条。B3/B4把人工图标纳入revision/撤销，视图偏好不污染主题归属。唯一R0仍需验证真实导航/必要入口、目标链接、宿主scope、用户时间及覆盖、原生DOM与恢复、PAIA共存；此次原型不能代替。
