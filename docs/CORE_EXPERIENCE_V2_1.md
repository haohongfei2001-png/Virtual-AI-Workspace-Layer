# VAIWL 核心体验 v2.1：安静界面与主题独占时间分段

2026-10-10。对 PR #1 / 772e7c38 的定向修订，依据用户本次三点纠正。不是另一套产品研究，也不修改原始研究档案。v2 中“区间存在性浏览”和时间/来源/计数前台化的选择被本文件明确替代。

## 1. 已明确的纠正与替代关系

用户要求：时间在后台工作；主界面只需最近一个月仍活跃的主题及其活跃对话；不显示每个窗口/项目来源和计数；每个时间段有隔断，当前活跃主题不重复出现在上个月；窗口完全依附主题，旧窗口留在其主题内，额外点击才显示。

| v2 旧选择 | v2.1 当前约束 |
|---|---|
| 任意区间有发送就再次展示该主题 | 每个主题按其最近可靠活跃时间只落入一个时间段 |
| 八月和十月均有发送的对话在两个时间页分别出现 | 主题在当前段时，八月对话只在该主题内折叠；不在八月再造一张主题卡 |
| 每行发送日期、原生来源、卡片来源数/对话数 | 主题名称、对话名称、展开与按需操作；无逐项日期/来源/计数 |
| 常驻日期区间、时区、示例今天和范围工具栏 | 默认自动最近一个月；“以前”/“更早”负责历史访问；粒度在按需菜单，示例时钟只在原型设置 |
| 固定旧对话带出父主题到当前卡片区 | 固定为导航捷径，不提升父主题活跃性，也不复制跨时间段卡片 |

上述纠正为 OWNER_REQUIRED_V2_1。列数、初始预览行数、展开批次和固定捷径的精确位置仍是设计解法，未被自动批准。原生一致性、主题卡片、真实来源保留、可逆派生、账户隔离和人工修改优先均不变。

本次只修正时间展示归属，不替用户重新决定原有显式多主题 Placement。一个主题在时间轴只出现一次；同一对话若已被用户明确放入多个主题，各 Placement 内都完整依附其父主题，时间筛选不得新建或删除 Placement。

## 2. 默认界面与操作

默认页面只有主题卡片。卡片头是主题名、展开控件和按需菜单；行内只有可区分的对话名与按需操作。去掉日期、最近发送标签、原生 Project 来源行、来源数、命中/总量比、对话数量、区间外/覆盖状态徽标。不要改为 hover 后大量浮出这些信息，也不要把它们换个位置组成信息面板。

一个主题内默认展示其所属段内活跃的对话；旧对话通过“以前的对话”展开。大量对话沿用已有的分批展开/单主题聚焦能力，但文案只写“显示更多”，不显示剩余数量。展开必须可以到达集合真实末尾。

全局“以前”进入前一个滚动日历段，之后可“更早”“较近”“回到现在”。历史也是主题页，不是所有窗口的日期索引。默认不出现精确日期和时区。1/3/12 个月及全部历史保留为按需选项，不要求用户配置后才能使用。

时间无法判定的主题保留一个折叠的“其他主题”入口；已确认活跃主题内部的未知时间对话放在“其他对话”中。它们不是待用户审批的任务，也不标成已确认的旧对话。具体用词属于当前解法；不能为了界面清爽猜测日期或丢弃未知记录。

搜索结果同样不逐行展示来源/时间/计数；需要时可穿透全部已知历史，点击不改变活跃事实。当前聊天页不增加 VAIWL 来源行，不重复播报时间规则。原生界面本身的 Project 导航不被这项去冗余要求删除。

底层仍保存原生来源、链接、范围、时间证据与必要统计，但没有这些常驻显示。新建时实际原生目的地、独立原生写入的准确目标/旧新名和敏感授权仍在当次明确操作前核对，不能把“主界面不显示来源”解释为可以盲写。普通显示编辑不得触发原生写入。

## 3. 时间是主题的唯一分段依据，不是事件检索视图

保留 v2 的当地今天 T、IANA 时区、滚动日历月和原始锚点夹取规则。默认 m=1；B(j)=T 减 j×m 个日历月。W0=[B(1),T+1日)，Wk=[B(k+1),B(k))（k≥1）。不改成自然月或固定天数，也不从已经夹取的边界连续减月。

以 T=2026-10-10 为例，当前段为 09-10—10-10，上一段为 08-10—09-09。**这些边界用于后台计算，不要求逐卡或逐行显示。**

在当前有效 Placement 集合中，取该主题所有获准成员的可靠用户新发送事件的最新时刻 L(t)。时间证据足以确认最近段时，将主题放入唯一满足 L(t)∈Wk 的段 k。对不同段 i、j，主题集合必须互斥：Topics(Wi)∩Topics(Wj)=空集。

例：PAIA 有十月的新输入，也有八月的开发/设计对话。PAIA 只在当前段；八月对话仍在 PAIA 的“以前的对话”，不会进入上个月主题页。一个最后在九月五日使用的独立主题进入上一段，连同它所有更早对话一起保留。

“在某月曾经有活动”和“现在属于哪个最近活跃段”是不同问题。本产品当前需要后者。v2 所说“只存 lastUserSentAt 不够，所以八月必须再次命中”不再是前台需求，也不能继续作为验收标准。可保留 UserSendEvent 以验证时间、去重、撤权重算和处理纠正；不必为本需求建设完整事件浏览器。

窗口/月份切换仅选择投影集合，不修改 Workspace、Placement、原生 Project、标题或消息。归属纠错可能合法改变主题成员最大时间，但绝不能把纠错操作时间当作用户发送。访问、AI 回复、改名、固定、导入和消息编辑时间均不是新发送时间。

## 4. 对话依附父主题

先确定父主题的唯一段，再划分卡片内部对话，不能先把窗口按月散开后反推主题。

对已确认属于段 k 的主题：对话最近可靠新发送时间也在 Wk，则进入默认列表；可靠时间早于 Wk，则留在本主题的“以前的对话”；缺少足够证据确认的记录进入本主题的“其他对话”。不能把较早成员作为独立时间卡片输出。

例如，历史主题最近在上一段使用，它的默认列表呈现那一段仍活跃的成员，更早成员仍在同一主题内折叠。进入一个单独聚焦的主题，内部划分依据该主题自己的段，而不是用户之前正在浏览的其他段。

一个旧主题后来获得可靠的新发送后，整张主题进入当前段；旧段不再保留第二张卡。未重新发送的旧成员继续折叠。窗口链接、系列、人工名称及归属不变。仅打开旧对话不会发生这种迁移。

## 5. 可信时间与未知边界

最近可靠事件不是“观察到的最大时间”就必然代表真实最后活动。进入当前段有可靠正向事件即可，哪怕其他时段不完整；判定更老的段还必须有证据排除直到当前评估时点的更晚用户发送。一个旧快照不能证明快照之后没有新活动。

历史分段需要有效的时间覆盖/新鲜度证据，不能靠旧 timestamp 猜测。主题若有一个成员可能有未观察到的更晚发送，并且没有已知当前段正向事件，就保留为未知，不强塞到历史月。未知记录不占据已确认活跃集合，不消失，也不需要用户日常维护。

默认最大活动摘要包含：latestVerifiedUserSentAt、事件引用、coverage/freshness、scope/epoch、成员 revision。保存它不免除消息级来源验证；不保存全文也不意味着时间元数据不敏感。

系统时区/午夜变化重算同一锚点的所有段。未知新鲜度不能因时钟推移自动变成“确认不活跃”。当前原型固定示例今天，运行环境时区只用于合成计算；没有实现真实宿主午夜调度。

## 6. 当前对话与固定

时间归档控制“在哪里列出主题”，不控制“能否继续已经打开的聊天”。当前原生对话、输入节点和阅读位置不能被历史翻页/主题折叠关闭。离开聊天查看主题时，只保留简短“正在查看＋对话名”返回入口，不加区间、日期或来源解释；在聊天页不重复这条横幅。

人工固定提供快捷引用，原型将它放在侧栏。固定旧主题不在当前月份造一张例外卡；固定旧对话也不强制展开或提升父主题。其卡片仍只属于唯一时间段。点击固定项可以直接进入对应主题/对话，受正常 scope/权限限制，不改变活跃性。工作集同理是访问捷径，不是第二套时间归档。

## 7. 逻辑契约与工程影响

沿用现有 UserSendEvent、TimeCoverage、TimeWindow、Workspace/Placement/Workset。ActivityProjection 的语义修订为 TopicRecencyPartition：topicId、唯一 bucket 或 unknown、最新有效时间证据、成员默认/旧/未知集合、scope/epoch 与事件/覆盖/Placement/窗口版本。无需新建一套正式数据库实体，实际 schema 仍待实施阶段。

计算：scope/权限 → 有效时间与覆盖 → 主题最近活跃段 → 该主题所有成员内部折叠 → 同版本提交。固定/current 只生成快捷引用，不改分段。日期、来源与计数不由卡片 render 输出；必要内部计量不对用户假称全账户总量。

R0-02 新增：最大可靠发送摘要的语义与新鲜度，历史候选之后是否仍有覆盖缺口；不要把缺失时间变成访问时间。R0-04/C1 新增：当前/上一段/更早主题集合互斥、旧成员依附、主题重激活整组迁移、打开旧窗口零激活、固定不复制卡片、原生节点与选择区保持。B3/B4 用同一 revision 的主题分区和成员集合，不再按任意历史事件分别投影主题。C2 从首屏消除时间/来源/计数噪声。其余 A–G 范围和授权不变。
