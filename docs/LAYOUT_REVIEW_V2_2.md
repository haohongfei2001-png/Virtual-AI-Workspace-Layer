# v2.2 布局候选：内容先出现，卡片不再为空信息撑大

2026-10-10。基于现有 Draft PR #1 / `0916a66f9c54b26d454ad4c346e32334749e6517` 和用户最新截图反馈的增量设计。不是重新研究；不改变 [v2.1](CORE_EXPERIENCE_V2_1.md) 的主题独占分段、父主题/旧窗口、人工保护或原生数据边界。布局参数仍为候选，不因本次交付自动批准。

## 1. 需要解决的不是再删几个字

v2.1 去掉时间、来源和计数后，仍然保留了双层顶部导航、可见的“主题”大标题、半屏宽卡片，以及被同行最高卡片决定的下一行位置。结果是有用信息减少、旧空间分配不变。

本轮方向：删掉没有独立任务的 chrome；围绕真正的主题名和窗口名重新分配尺寸。不能再加 AI 摘要、最近活动文案、来源徽章、统计、图标插画或空白占位来填满卡片。

## 2. 顶部与导航的取舍

主题概览不再自建主区 ChatGPT 模型下拉，不再显示右上角品牌徽章、双段模式开关和设置整条横栏，也不再单独占一行显示“主题”大标题。主区直接从主题卡片开始；无障碍标题保留但不占视觉空间。

“回到原生”是侧栏底部的单一动作，不隐藏在多级设置里；启用时反向为“启用主题视图”。VAIWL 第三方身份与设置收在导航底部。主题选项放在侧栏主题入口旁。导航收起或窄屏时保留窄工具列，仍可展开导航、搜索、访问以前、打开选项或退出。未知时间、以前主题、固定和当前对话的可达性不删除。

这不是授权删除真实 ChatGPT 的模型、工具、账户、原生 Project 或其他必要入口。删的是旧原型重复搭建的导航横栏。正式宿主已有 toolbar 的保留/融合必须通过 R0 的当前页面所有权与能力验证；不能照着静态原型遮掉原生控件。

历史页只增加必要的紧凑返回/较近/更早操作，不恢复大标题和常驻日期。离开聊天的继续入口移至导航，不在主区再加返回横幅。当前工作集的完整行为暂沿用，不借本次布局选择擅自批准 PD-02。

## 3. 内容比例卡片

一个主题仍是一张卡片。卡片只包含主题名、紧凑窗口行和必要的展开/按需操作。主题名比窗口名稍重，不使用品牌底色、统计或摘要。窗口保留可区分名称，长名称视觉省略但不截断保存，按需可查看/编辑完整名称。

默认卡片不再占半屏；本候选按可用宽度采用 1–4 个窄列，常见桌面卡片约 280–340 CSS px，窄屏按容器收缩。单个主题也不自动拉满整个主区。高度由实际内容决定，没有统一最小高度：一个窗口就是小卡，多窗口自然更高。

普通指针窗口行约 32px，高密度没有靠把文字缩成小字实现；窗口文字从旧例的13px调整为14px。触控指针保留更大的操作区域。这些是原型参数，尚未完成当前登录态 ChatGPT 字体/像素校准。

卡片初始展示最多5个默认成员，仍可逐批显示完整集合；不把第6项起的活跃窗口错误归入旧窗口。展开提示不显示数量。旧窗口、时间未知成员始终保留在父主题内。底部“显示更多 / 以前的对话 / 其他对话”在折叠态紧凑并排，展开后内容回到同一卡片，不再各占一条空的分隔栏。

大量成员可沿用菜单中的单主题查看，宽度上限候选560px。它不是新层级或窗口副本。卡片折叠、显示更多及旧窗口展开后保持逻辑焦点。

## 4. 不让短卡下面留下整行空洞

| 方案 | 判断 |
|---|---|
| 固定等高或普通行网格 | 一张长卡会在旁边短卡下形成大空洞；不继续使用 |
| 每次重新按最短列排布 | 空间紧但展开/异步更新容易让别的主题换列；本候选不采用 |
| 窄列独立纵排、稳定分配 | 当前候选：同一列内自然衔接，展开只向下推动本列后续卡片，不重新平衡其他列 |

响应断点变化时按原稳定次序重新分配。每个主题仅一个DOM实例，读屏与Tab按实际列内DOM顺序，不用正tabindex伪造另一套导航顺序。跨列扫读的用户表现仍待体验比较，不能把“空间利用率高”当成已证明最优。

## 5. 没有改变的数据语义

保留全部91主题/345对话和 PAIA 60个成员。原消息、事件、来源和Placement没有为布局删减。为避免压力样本所有卡片都只写“方案比较/细节验证/阶段总结”，仅给26个合成主题的78条示例行增加预写显示名；不是模型输出，也不是原生改名。人工显示名优先级仍在其上。

当前主题不重现于上个月；旧窗口仍留父主题；固定只是捷径；访问/AI回复/改名不激活；未知不伪造时间。15个日期、最新时间、主题分段与成员划分函数逐行字节保持一致，并记录哈希。
