## Confirmed gap and contract

`HOST_INGESTION_PASS start` records a private scheduling hint with an original dual-clock 30-second validity window (`host-ingestion-pass-owner.mjs:11–16,41–43`). Terminal messages and invalidation retire it, but merely reaching that deadline has no driver. `isPending()` can retire it, yet current production code has no caller of that method. `isIdle()` correctly remains a pure local snapshot; a lost terminal IPC can therefore leave its unfinished hint busy indefinitely with no actual request still running.

The actual binding/UI/ingestion service regression starts a pass successfully, renews the real document transport at 15 seconds, then delivers no end/cancel. At 29,999 ms the service correctly denies idle; at 30,000 ms the baseline still denies it. The candidate expires the RAM hint and allows the otherwise-idle authenticated preflight. Replay of the same start stays denied. This is not a synthesized end, completed ingestion, inventory coverage, authorization or idle permit for other work.

Round355 explicitly left conservative residual records as later lifecycle work while requiring idle queries not to read clocks or clean up. The patch preserves that query contract and the existing validity window. It does not discard recovery plans, backup transfers, send evidence or user confirmation work.

## Bounded implementation

- At most one expiry timer per retained producer, within the existing 128-producer bound.
- Remaining delay comes from the original request-entry wall/elapsed timestamps, including time spent validating the start. Duplicate start and document renewal do not restart it.
- The original current/clock/authority guard terminates the hint. Early firing may reschedule only the original remaining time.
- Timer marker and exact producer-entry identity reject cancelled/late callbacks. End/cancel, newer pass, invalidation, producer pruning and stop cancel owned timers. Tombstones remain.
- `runs` and `requests` are unchanged; a real underlying browser wait still blocks idle after both hint expiry and the six-second RPC timeout, until it actually settles.
- No new network/read, persistent state, retry of terminal IPC, grant reuse, expanded deadline or idle-query mutation.

The unapplied patch also adds `runTimers:false` to the existing idle-test clock helper and uses it in the old pure-query test. All original assertions remain: with the expiry callback paused, querying idle still cannot retire a stale record. The new integration cases separately execute the timer.
