# VAIWL v2.6：图形回看与原生功能完整保留

2026-10-11。以 PR #1 的 `136f594f0f6c0b39ca2dcf1eaf5afd389ed689dc` 和实际 v2.5 HTML 为基础。用户在讨论后明确要求“按照你的建议，修改”。本文件将已讨论方向落实为设计要求；不是正式扩展实现，也不是原生能力已验证声明。

## 1. 本次采纳与继承

本次确定：历史控件不再常驻“以前／看看以前”等文字；功能所有权与入口是否折叠分别判断；原生功能不能无故消失或降级；原生搜索不能被局部派生搜索冒充；真实 dot 头像、名称、字体及状态沿用宿主；任务、授权和未知新入口不能被主题活跃性过滤。

不变：v2.1 的主题按最近可靠用户新发送独占一个滚动日历段，旧窗口仍依附父主题；v2.4 的连续侧栏、手动开合、同族主题图标和当前访问例外；v2.5 的原生聊天所有权和顶部工作空间返回。原始研究与旧版原件不改写。

本文件与更新后的 INTERACTION_SPEC 是本次原生功能安排及图形回看的当前执行依据。旧版“侧栏搜索＝本地派生搜索”“原生功能＝说明弹窗”“全部主题管理页为日常回看必经路径”等冲突解法不再执行。精确尺寸、图形辨识效果与宿主映射仍需实测；用户采纳方向不等于这些结果已经通过。

## 2. 图形控件：位置、形态、结果共同表达意义

| 位置 | 常态外观 | 动作与不变量 |
|---|---|---|
| 主题卡片／侧栏子列表底部 | 居中的低对比下箭头把手，无常驻文字 | 只展开已确认较早的窗口；上箭头收起；不混入近期溢出或时间未知记录 |
| 整个主题区底部 | 小型时钟回转箭头，无常驻文字 | 进入前一个互斥时间段；再次进入更早一段，不先进入总目录 |
| 历史状态 | 后退／当前／向前图形控件 | 较近一段、回当前、较早一段；不显示月份、日期或数量 |
| 工作空间返回 | 侧栏既有顶部与折叠轨中的工作空间符号 | 回到刚才的主题／历史视图、滚动与展开；不是关闭扩展 |

旧窗口把手与整页历史图标不可同形同义混用。语义通过所属容器、方向、按下后的局部展开或整页更换体现。辅助保留 `aria-label`、`aria-expanded`、有效 `aria-controls`、键盘焦点和简短 hover/focus 提示。没有常驻字不等于没有可访问名称；触屏不以 hover 为必要条件。真人初见理解尚未测，不声称图形天生无歧义。

近期窗口很多时，在近期列表内部逐批显示或采用已批准的独立容量机制。旧窗口把手不承担“显示遗漏的近期项”。未知时间记录由主题内查找、派生全记录查找和次级记录入口承接，不能消失、不能改判为旧。没有旧窗口就不显示空把手。空历史段不静默跳过；可返回或继续前一段，无法确认还有多少历史时不伪称已到全账户尽头。

## 3. 两个独立维度

所有权分类：`NATIVE_IN_PLACE`（原生原位），`NATIVE_ENTRY_ORGANIZED`（功能仍原生，入口可整理），`DERIVED_REFERENCE`（只映射导航引用），`VAIWL_OWNED`（扩展自有）。

可见性分类：直接、用户固定、一层可展开、上下文出现、原生专用页面。它们不是权限。折叠不能改变账户可用性、任务运行态或真实授权；隐藏无权访问入口也不能由 VAIWL 猜测实施。

“关闭扩展以后能找到”仅是异常逃生，不是正常的功能保留方案。任何既有功能在增强开启时都应有真实可达路径。保留图标但失去菜单、状态、批准或结果，同样算功能丢失。

## 4. 原生／映射／折叠职责矩阵

下表按能力类别登记，不是一份固定安装菜单。名称、存在性、顺序、图标、权限及当前状态取自实际宿主与账户；公开帮助页面不能代替该用户的运行证据。

| 功能类别 | 所有权 | 建议呈现 | 不允许的变化 |
|---|---|---|---|
| ChatGPT 标志、原生侧栏开关 | 原生原位；扩展开关独立 | 原位置与行为优先 | 不将标志改绑 VAIWL 首页，不生成第二个同名入口 |
| 新聊天、原生搜索及原生快捷键 | 原生原位 | 上方直接可见 | 不先弹扩展目的地、不用局部索引替换搜索、不占用原生快捷键 |
| 真实 dot／用户固定原生对象 | 原生入口整理，内部原生 | 原头像、名字、字体、状态直接保留 | 不换成主题图标、不用月活过滤、不伪造缺失入口或头像 |
| 聊天正文、流式生成、停止／重试 | 原生原位 | 原生聊天主区 | 不抓取后再渲染，不接管生成循环和动效 |
| 输入框、粘贴、拖入、附件、发送、语音 | 原生原位 | 原输入组件 | 不克隆或重建，不持久采集未发草稿，不吞 IME／快捷键 |
| 模型、思考与模式选择 | 原生原位 | 宿主实际提供的位置 | 不固定模型名单，不为简洁迁入扩展设置 |
| 搜索工具、研究、学习、图片、应用调用 | 原生原位 | 原生工具菜单及实际可用状态 | 不提供失真的重复工具栏，不替代额度／授权提示 |
| 复制、反馈、编辑、重试、分支、分享、会话菜单 | 原生原位 | 原生就近按需操作 | 不删按钮，不把派生编辑与真实删除／归档／移动混成一个动作 |
| Canvas、图片编辑、文件预览、代码及交互回复 | 原生原位 | 原生面板／专用页面 | 不将交互内容压成静态文本，不套固定聊天卡片渲染器 |
| Projects | 原生入口整理 | 保留入口；长项目列表可收起 | 派生主题不代替项目文件、指令、成员、共享与管理 |
| Space 或 Library 等资源区域 | 原生入口整理 | 沿用该账户实际名称；用户固定优先 | 不人为强造两个同义入口，不混淆原生资源与VAIWL工作空间 |
| Images、GPTs、探索／我的GPT | 原生入口整理 | 常用／固定直接，其余一层展开 | 不丢固定对象，不改GPT原头像或配置入口 |
| Plugins／apps／Skills等管理 | 原生入口整理 | 原有命名与权限入口可展开 | 不替用户批准连接、动作或安装；不共享 PAIA 授权 |
| Tasks、计划、Work／Codex及运行记录 | 原生入口整理；状态原生 | 历史列表可收；运行／待处理状态可达 | 不因没有用户新发送而隐藏通知、暂停、接管或批准 |
| 专用页面及新增原生能力 | 原生原位优先 | 只对实际存在者安排；未知节点保留 | 不用静态白名单漏掉新入口，不将专用页面强塞为普通聊天 |
| 账户、组织、设置、个性化、记忆、隐私、归档、订阅／用量、帮助 | 原生原位 | 稳定原生账户区 | 不收入VAIWL齿轮，不抹掉组织／隐私状态，不代答授权 |
| 主题、对话列表、显示标题、系列、工作集 | 派生引用或扩展自有 | 卡片／连续侧栏 | 不改变原生对象、链接、Project或模型上下文 |
| 图标选择、主题纠错、时间投影、备份／恢复、VAIWL退出 | 扩展自有 | 扩展入口清楚标识 | 不冒充宿主功能，不继承原生写权 |

此前讨论举到的专用能力名（包括 Sites、Health、Finances、Remote 等）不构成“用户账户当前都有”的判断，也不是默认菜单要求。实际出现则保留，不出现不补画；同样原则适用于未来新名称。

## 5. 原生搜索与派生查找分开

侧栏“搜索聊天”和宿主原有 Ctrl/Cmd+K 继续走原生搜索。其范围由宿主决定，可能覆盖扩展从未读取的记录；VAIWL 不冒充完整索引、不接管结果权限。

主题菜单和工作空间选项中的“查找主题与派生名称”是扩展自有查找，搜索派生名、别名、主题及已获准已知输入，注明已知范围，支持旧／未知记录。未来可实验安全的融合结果，但没有通过前不静默替换。原生搜索结果可以保留自己的来源／类型标记；“不显示来源”仅约束扩展新增的重复元数据。

原生“新聊天”也保持行为。仅当用户主动选择VAIWL的“在某主题中开始”时，才需要明确实际原生目的地；此派生动作不改变原生新聊天的默认语义。原生 Project 面包屑、临时模式、成员及权限提示继续保留。

## 6. 真实组件与宿主身份外观

正式实现优先保持原节点及其框架所有权、菜单portal、订阅和事件。不得把截图、HTML复制品、另画的头像／输入框称为复用。移动真实组件也并非自动安全：只有精确宿主版本下验证过状态、焦点、菜单和事件才可重排；否则保留原区域、只减少VAIWL自己的占位。

只替换已经确认由扩展承担的聊天导航子区域。未知原生节点默认保留；无法判断边界时保留整段原生区域，不用隐藏父容器的方法把未知子入口一并删除。扩展CSS/动画限定自有根节点，不全局覆盖宿主字体、按钮或动效。

真实dot头像可有颜色；用户自定义形象不受VAIWL单色主题图标规则约束。原名字体取宿主表现，外围只做非破坏性的对齐。未取得真实素材，本轮用明确的字母d占位，不声称恢复了用户头像或特定字体，也不提供字体文件。

## 7. 侧栏与页面连续性

上部原生标识、新聊天、原生搜索、可用dot；中部VAIWL当前主题展开与其他活跃主题头部；资源区保留原生Projects及用户固定入口，其余通过一层原生入口区展开；底部原生账户。VAIWL工作空间返回与设置／退出各自有身份，不与原生账户混合。

用户的原生固定优先于默认折叠。额外固定只改变入口可见性，不按几天点击频率自动洗牌。原生待处理状态位于不受主题滚动和历史过滤控制的位置；折叠轨也保留可发现的状态入口。增强原生状态时不复制执行／批准动作或改变其授权含义。

聊天、dot和其他专用页面打开后保留原生主区。若Canvas或其他工作模式需要额外空间，VAIWL只让出自己的区域；不任意关闭用户手动展开的侧栏、不挡原生工具。返回工作空间保留之前来路，浏览器后退／前进照原语义。不存在唯一派生来路时打开最近工作空间，不伪造浏览器history或把标志导航改绑。

未知原生功能不应用月活过滤；历史主题仅在当前访问它时保留单个临时上下文，不因此复制到当前段。

## 8. 原生功能保留验收与工程落点

每个实际存在的功能记录五格：入口、操作过程、结果、状态／权限、返回。全部满足才说该环境下该功能未被扩展新增阻断。文档列了多少功能不能当成多少功能已通过。

| 原任务 | 本次增量要求 |
|---|---|
| R0-00 | 清洁环境按账户／语言／布局盘点真实原生入口、用户固定、未知节点、dot外观及权限；不先假定静态名单 |
| R0-02 | 区分原生搜索覆盖与派生已知索引；不扩大采集来假装搜索齐全；时间验证仍按v2.1 |
| R0-03／04 | 真链接进入原生聊天与专用页；原组件所有权、菜单portal、输入／动效、五格保留矩阵、返回及退出；未实测标NOT_RUN |
| R0-05 | PAIA和VAIWL只操作各自区域；正常搜索、原生资源、动态状态和输入不争抢，不改PAIA仓库 |
| B3／4 | 派生图标／展开／固定偏好与原生账户、宿主固定、任务状态分开；scope/epoch与revision失效规则 |
| C1／2 | 第一版完整体验就交付无常驻文字的图形回看、连续侧栏和原生入口共存；不是C5美化 |
| C4 | 原生搜索仍可用，派生查找单独且范围诚实；历史／未知可达 |
| C5／6 | 图标初见可发现性、键盘／触控／读屏、原生对照与故障恢复，不能用截图替代 |

沿用唯一R0与A–G计划，不创建平行验证队列。此轮只做离线原型与文档，R0真实探针和清洁账户仍需另行授权；单个新入口受阻只关闭对应的重排策略，不能让整个产品陷入无限验证。

## 10. 本轮原型与真实证据

v2.6直接修改实际v2.5；15个原时间／分段函数的原源行保持。四套合成场景仍为2/3、6/17、14/54、30/110活跃主题／窗口，压力91主题345窗口与PAIA60成员不删减。这不是用户均值调查。
