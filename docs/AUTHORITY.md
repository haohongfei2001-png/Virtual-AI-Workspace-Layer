# 文档效力与批准边界

日期：2026-10-10。状态：PROPOSAL_FOR_REVIEW。

## 1. 三类效力

**本轮明确要求固化的架构边界（REQUESTED_BASELINE）**：原生数据和 Project 归属不变；独立、可逆的语义投影；稳定工作区、对话系列、当前工作集；原生/派生标题分离；重构导航而保留原生聊天、输入框、模型和工具。这些是本提案与后续验证的约束，不是实现成功声明。

**上一轮研究推荐及本轮工程化展开（PROPOSED）**：具体布局、默认动作、工作区形成方式、模型选择、阈值、存储字段、任务拆分、实验样本规模等。工程化展开是把原研究变成可执行契约，不是重新设计一个产品；未批准项在 DECISIONS 中保留替代方案。

**真实操作授权（EXECUTION_AUTHORIZATION）**：本轮仅文档分支与 Draft PR。安装探针、访问测试账户、发起云调用、原生改名或发布，不能从设计文字推导授权。新一轮必须按任务范围确认。

## 2. 优先关系

用户最新明确授权与安全边界 > 本文批准边界 > 已逐项记录的决策 > 相应专题规格 > 开发任务与验收 > 原始研究/原型作为参考。

原型可展示方案，不能覆盖安全不变量；原稿中的“选择”“建议”“主架构”不等于用户批准所有像素和默认交互。原稿与原型不一致时，两者都记录，不自行把方便实施的一方设为 Canonical。

`STATUS.md` 是唯一任务状态指针；`DEVELOPMENT_PLAN.md` 是依赖和交付范围；`DECISIONS.md` 是批准登记。任何一处说“待确认”都不能被另一处的阶段计划消除。

## 3. 证据标签

| 标签 | 能证明什么 | 不能证明什么 |
|---|---|---|
| ARTIFACT_VERIFIED | 本轮读取的文件、CRC、哈希、包内一致性 | 原结论正确或产品实现 |
| RESEARCH_SOURCE | 原报告固定 SHA 源码阅读及官方资料记录 | 本轮重新核查的最新事实、已安装行为 |
| VENDOR_CLAIM | 商店/厂商公开声称某功能 | 独立实测质量、合规或可靠性 |
| PROTOTYPE_SIMULATION | 原型示例 UI 及原记录 20 项断言 | 真账户、原生 DOM、持久化、AI 泛化 |
| BROWSER_FIXTURE | 真实 Chrome 上的受控合成宿主/探针 | 真实 ChatGPT 路由与账户能力 |
| LIVE_HOST | 明确授权的干净账户在真实 ChatGPT 的精确实验 | 其他浏览器/账户/版本的自动保证 |
| TARGET / NOT_RUN | 拟定指标或未进行实验 | 已达标或失败 |

此次新增证据只有原件读取校验、原型源码/截图核对和新仓库读写核对；不新增 LIVE_HOST 或真实模型证据。上一轮动态网页信息保留为研究时点记录，本次不重新做竞品调研，不用它写实时市场或平台承诺。

## 4. 批准与冲突处理

每个产品决策记录 ID、方案、理由、状态、批准者/原话/日期和影响任务。只有明确确认对应决策才填写 APPROVED；未明确者保持 PROPOSED。合并文档可只是保存提案，不自动批准全量实施。

安全与恢复存在不可验证项时，只关闭依赖该能力的路径。不得把高风险写入未通过扩大成“所有本地工作不能做”；也不得以快速交付为由偷偷替换为私有接口或降低账户隔离承诺。
