# 隐私、权限、安全与恢复 · v2.8候选

本轮只写设计与计划，无Mac、真实浏览器、私人聊天、模型或原生Project操作。基线实际测试与尚未通过项见[证据登记](research/V28_BASELINE_AND_ACCEPTANCE.md)。新机制不降低既有B1–B5和原生保留要求。

## 1. 身份与最小数据不变

扩展用户、当前宿主account/nativeSpace、来源scope分开；三者可信匹配且当前epoch有效才展示或写入敏感资产。Project不是安全账户边界。安装/Profile/tabId、头像/邮箱字样、手选库、API key/OAuth本身均不证明当前网页身份。

切账户/组织/路由先撤旧投影和旧任务，再确认新范围；每个异步返回、事务和原生动作前复核。PR #6已见sender.url滞后于当前browser frame，PR #14又见旧DOM和路由不一致；不能退回“URL或marker存在即身份成立”。

默认最小用户输入/必要元数据；助手正文、未发送草稿、Project文件/指令和完整对话镜像不因主题语义分析而自动授权。主题标题、别名、向量、归属、日志、密度样本也可能敏感。

未归类/时间未知/无权限分别表达，不凭显示需要改变证据。临时聊天和访客会话不升级为持久可靠历史；共享链接不冒充自有ConversationRef。

## 2. 三层许可与原生Project风险

页面观察/持久索引、云处理、原生创建/改名、同步/PAIA分别授权。**主题分类同意不是创建Project同意；同名偏好不是任意重建许可；原生新建聊天也不是替用户发送。**

本轮官方资料核验：原生Project具有文件/指令/记忆，共享成员有对应可见性；移入聊天可能改变上下文。项目的模式/记忆/工作空间限制必须在目的地选择时尊重，不能为“隔离”默认切project-only而损失用户需要的功能。当前官方说明还列出project-only下Work不可用，这应进入能力核验而非硬编码替用户变更。[S28-01]

默认新建为用户确认的私人目的地；不自动邀请、分享、复制旧文件/记忆/上下文。既有共享Project只能显式选择并核验成员可见范围；共享状态改变后暂停原生动作。模糊、缺权限或结果不明时原生流程停止，但派生组织/查找继续。

## 3. 可信创建通道与预算

创建计划由扩展可信界面审阅精确scope、workspace/nameSnapshot、目标Project、原生语义及次数。真实创建默认串行。确认前不写；派发前先持久记账，跨tab/worker/Profile/重试不可绕过任务级上限。默认最大1次Project创建、1次入口打开、0次消息自动发送/移动/删除/分享。

原生点击/DOM出现不是服务端事务成功；须同scope稳定ID和目标属性读回才VERIFIED。已派发但超时=UNKNOWN，不自动再创建。取消/撤权停余项；已经创建的原生Project/聊天不随本地undo或关闭扩展删除。

同一安装内共用账本；测试任务创建的新Profile沿用外层任务预算。独立浏览器安装/设备之间没有共享账本，不得声称仅靠本地CAS全局去重；缺原生幂等/协调时限制为单执行实例并要求核对。

本地日志CAS能防本扩展重复派发，不能保证远端exactly-once。已派发动作崩溃后只有只读核对，不从备份恢复grant或自动重发。用户改名或另行操作后结果保留CONFLICT，不用“修复”覆盖。

PR #14有跨run发送预算失控的执行记录；本轮把全流程预算作为正式验收反例，不允许用新输出目录/新Profile重置。实验预算和产品用户批准分别记账，任何被拒批准不换通道重试。[R14]

## 4. 数据渠道与提示注入

页面当前可见、用户主动搜索、官方导出、被动响应逐条单独审查；页面能显示不等于可全量读取。当前没有验证普通扩展可用的ChatGPT原生Project创建API；API平台projects接口不能替代。[S28-02]

PR #14仅在已检查访客DOM/初始化/自然响应中未证实原始用户发送时间；HTTP Date/接收时刻/revision不可代替。这个UNKNOWN不证明所有匿名渠道不存在，也不能扩展为全账户历史已知。[R14]

导出只在资格与格式/范围验证后作为快照，旧快照不证明之后无输入；不同账号/工作空间的导出可用性不同。[S28-03] 任何数据包中的role、source名、verified字段均须经过特权来源核验，不由文件自签名认证。

聊天/导入/模型输出是数据，不得成为“创建Project、调用API、解除保护”的指令。模型只返回有限候选ID与证据，不返回任意URL/工具代码。ZIP/JSON校验字节、深度、解压路径、字段、ID/分支与恶意内容；未知格式拒绝，不eval。

## 5. 自适应的隐私与稳定性

密度只在当前授权scope计算，默认留本机；不新增使用行为上传、遥测账号或云模型。统计已知总体而非推断不存在的全账户分母；未知数量/覆盖和原生权限是启用自动的门槛，不是可以省略的性能细节。

H改变不生成UserSendEvent，不移动主题、不删除记录、不给D2更多文本读取权。手动固定总是优先；历史视图和原生输入/生成中的状态不因另一个tab发布偏好被打断。决定/证据版本可审计，日常UI不堆统计和来源。

## 6. 恢复与退出

延续B5校验checkpoint＋连续人工patch、安全inverse和损坏拒绝；不能用全库旧快照覆盖后续人工修改。备份仅获准人工资产与必要引用，可含创建策略/手动H，不能携带执行授权、自动待派发动作、密度可信状态或过期消息授权。

恢复的Project引用需要重新核验，不自动新建缺失项目；恢复的自动偏好从当前证据重新评估。损坏/配额/并发拒绝时保留原库，原生对象从不删除。schema升级和F1分片迁移不放宽旧大小/超时护栏。

受控退出撤自己的DOM/样式/属性，不复制输入框、不自动刷新。浏览器禁用/卸载/freeze可能无法执行清理：原生可用、布局干净、数据保全、操作停止分别测试，不能拿B4合成冻结通过替代真实ChatGPT。PAIA共存仍独立验证，不修改PAIA或依赖未经建立的共享协议。

## 7. 来源与实施门槛

[S28-01/02/03] 与 [R14] 的固定链接、核对日期及不确定性统一列于[来源登记](research/V28_BASELINE_AND_ACCEPTANCE.md#公开来源与时点)。这不是法律意见或平台许可证明。用户同意、Chrome权限、竞品上架都不能替代实际渠道与发布条款核验。

普通派生能力的批准不能启用真实创建；真实创建的批准也不能启用模型、同步、共享、历史抓取或原生改名。新增门槛映射至原R0/E阶段，不另建无限审计流程。
