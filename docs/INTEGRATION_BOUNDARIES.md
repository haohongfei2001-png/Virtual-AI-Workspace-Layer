## 2. 产品与数据所有权

VAIWL：对话引用、工作区、分面、显示身份、系列、tab 映射、工作现场、原生写入回执和上述任务必要索引。

PAIA：输入原始档案、用户可编辑内容、思想库/Personal Topics、AI Context、提示词复用及其权限。

同名 PAIA 工作区和 PAIA 思想主题不是同一 ID；可显式映射但不共享可写 owner、不双向自动合并、不继承授权。新产品必须不用 PAIA 也能工作。

## 3. 当前就需要的共存，与未来数据集成分开

**共存是 C 阶段前的兼容门槛**：在同一页运行仍不遮挡输入、抢焦点或重复写 DOM；R0-05 要验证，不可推迟到可选生态阶段。

**数据接口是 G1 的可选能力**：未来版本化、白名单、明确用户同意的本地扩展通信，只提供必要引用/最小用户证据；当前没有已验接口。不能为减少重复采集而共享私有 IDB、窃读对方 DOM 或复用 page message 作为信任。

## 4. 运行 owner 与回退

同一导航区域一个 owner。ACS 投影存在时，不争抢或悄悄禁用它；提示用户选择，VAIWL 可以先原生/只读降级。CTM 与 VAIWL 不允许同时拥有 native-title writer，未能证明单 writer 时 VAIWL 写入保持关闭。

PAIA 输入浮板/候选板继续由 PAIA 拥有；VAIWL 不变宽、不移动、不修改它。未来可交换有限的布局占用/版本信号，不能假设现在可用，也不能把第三方发来的“安全”声明当授权。没有协议时用保守布局边界；冲突就减小/收起 VAIWL，而不遮原生输入。

R0 测试基线至少含无扩展、VAIWL 探针单独、PAIA 单独、两者共存。记录实际加载的 PAIA 版本、构建哈希、顺序与主机变体，不能只记录 GitHub main。安装/重载顺序反转、PAIA 展开/收起/搜索、输入框增高、IME、原生菜单、两个扩展各自故障恢复都单列。

所有数据为清洁账户中的合成示例；若需要修改 PAIA 才能继续，停止并报告所需协议，本轮/后续 VAIWL 任务不得跨库顺手修。
