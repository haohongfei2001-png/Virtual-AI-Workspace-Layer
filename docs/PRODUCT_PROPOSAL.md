# VAIWL 产品提案 · v2.8定向整合候选

> **产品定位收敛：一套代码库，Free先上线，Pro后开发。** Free按真实ChatGPT Project/成员/原始标题显示，独立保留全部已知无项目窗口，并把活跃度的最终准确和数据不足时的可用排序作为核心价值；Pro才在无项目窗口上增加AI虚拟主题及派生命名。下文关于稳定虚拟Workspace、系列、跨Project派生关系的长期研究**保留为Pro候选，不是Free首发默认**。见[FREE_PRO_PRODUCT_SCOPE](FREE_PRO_PRODUCT_SCOPE.md)。


定位不变：让用户在真实ChatGPT中按长期工作事项找到、辨认、组织和继续对话，而不是再维护文件夹后台。原研究、竞品资料与v2.7批准原件继续留档，本轮不重做市场研究或全产品视觉设计。

## 1. 本轮要改善的完整闭环

**创建主题 → 在主题内开始工作 → 真实原生Project/聊天按用户选择建立 → 成员和手工命名可靠保存 → 按适合当前工作密度的区间显示 → 原生继续 → 稳定返回与恢复。**

这个闭环不依赖AI：手工主题、单窗口、明确目标内新建和人工归属先有完整价值；AI只减少找归属/短标题/关系建议的成本，不是允许主题存在的裁判。

北极星仍为进入正确工作的时间与错误率，辅以纠错/维护成本、原生功能受扰、范围安全和恢复成功。卡片数、API调用数和测试项数量都不能代替实际收益。

## 2. 对三项需求的选择

推荐首次在主题内新建时明确确认同名原生Project，并在将来复用已绑定目的地；真正Project未验证时保留原生UI辅助路径，不能冒充创建成功。主题与Project多对多，新聊天默认目的地最多一个，原生上下文不被聚合。

允许0/1/多窗口主题，按工作对象/目标稳定成立。窗口多只触发布局/查找问题，拆合必须有独立目标证据并经用户预览。原生Project不随主题拆合或改名自动改变。

将固定30日作为兼容值，研究有效H=7/14/30/60/90的密度自适应。主题归属与活跃证据不变，手动优先、未知不造假、抗抖且会话内稳定。主界面不重加时间/来源/计数；设置中可手动查看范围。

这三项是一个机制系统，不是三个独立的小补丁。细节和被否决方案见[CORE_MECHANISMS_V2_8](CORE_MECHANISMS_V2_8.md)。

## 3. 原生能力与信息架构

Workspace、ConversationRef、Series、Workset继续分工；默认信息层级只有主题卡与紧凑窗口，不增加复杂嵌套文件夹。多主题长对话优先引用/片段，不复制消息。主题页直接显示工作，阅读区真正使用宿主组件。

只替换已核验的导航子区域，未知原生入口、固定、dot、账户、模型/工具、授权/错误全部保留。关闭扩展是异常退路，不是用户使用原生功能的日常前置步骤。主题＋不挟持原生“新聊天”；派生搜索不替换原生完整搜索。

保留原v2.7的标题区、图标词汇、卡片边界、无字箭头与单一返回。此前早期提案“仅少量继续入口用卡”“蓝白/毛玻璃候选”是历史，不再覆盖已批准的主题级卡片和原生一致设计。

## 4. 数据、隐私与外部边界

本地组织是用户资产，不是可随时重建的缓存；B1–B5/F1的同库、CAS、备份/恢复与人工约束复用。仅保存获准引用和最小证据，未知格式/未知时间保留，不抓取助手/草稿/Project文件充数。PAIA仍管理输入档案、思想及AI Context，双方无共享写库/授权。

原生Project有上下文及共享/权限影响，创建需要独立准确同意；普通派生操作仍只改显示。没有验证普通扩展可用的ChatGPT原生Project创建API，API平台Projects不可代替。数据渠道和发布条款需要真实核验，不以用户同意或竞品存在推导可抓取全部历史。

## 5. 完整旗舰目标与已知差距

保留原A–G全路线：可靠数据接入、稳定主题/系列/工作集、搜索/片段/手工纠错、原生兼容和恢复、可选模型与原生改名、规模性能、加密同步、发布与PAIA生态。阶段按依赖拆，不以MVP降低目标。

真实数据/账户/Project、模型质量、实际用户收益和生产全链尚未证明。新需求不要求推倒已完成工程，但同样不能用合成100k/模板1200条宣称自动归类与自适应已成熟。当前仅候选文档到位，后续以[DEVELOPMENT_PLAN](DEVELOPMENT_PLAN.md)与[验收矩阵](research/V28_BASELINE_AND_ACCEPTANCE.md)推进。
