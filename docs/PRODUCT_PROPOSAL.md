# VAIWL 正式产品设计提案

状态：PROPOSAL_FOR_REVIEW。依据：原研究 §0–5、§11–12、§16–20；完整来源与逐节映射见 [SOURCE_REGISTER](research/SOURCE_REGISTER.md)。本文件不重新提出另一个产品，不把原型选择升级成批准。

## 1. 定位与目标

VAIWL 是 ChatGPT 原位的、可逆的个人工作环境：识别同一长期事项，为其对话提供稳定身份、连续关系与返回入口，让用户知道“我在做什么、相关工作在哪里、从哪里继续”。不是新聊天客户端、文件夹后台、通用浏览器管理器或个人知识库。

主要使用情境是数百至数千条对话、多原生 Project、多个并行窗口、跨周/月持续工作。核心问题不是只缺文件夹，而是事项被拆散、标题不可区分、前序和最新窗口不明、恢复时上下文边界容易误判，以及整理工具本身制造维护成本。

北极星指标：重新进入正确工作所需时间及错误率。辅助指标：每周纠错时间、无依据命名/组织漂移、错误来源/系列选择、恢复成功率、原生功能受扰率。聊天整理条数、目录数量、AI 使用次数不能代替这些结果。

## 2. 本提案的核心架构

独立派生层保存工作组织；原生聊天、链接、消息和 Project 关系仍由 ChatGPT 管理。导航是稳定工作区、明确对话系列与临时工作集的组合。原生标题是观察事实，派生标题是带 owner/revision 的用户资产。

导航、工作区概览、短标题、卡片、工作集与切换可以深度重构；原生聊天区、输入框、模型选择、附件、工具状态仍留在原位。关闭派生只撤除自有显示；已经另行授权完成的原生改名不会随开关自动撤销。

三条不可混淆的语义：聚合不合并上下文；可见不等于拥有全账户历史；派生不等于可丢弃缓存。人工命名、排除、系列与工作现场都是需要恢复的资产。

## 3. 竞品差异，继承研究而非重查市场

以下是上一轮记录的官方/厂商说明，非本轮安装实测或实时排名。原生平台条目使用原来源 S1–S6；供应商条目是 VENDOR_CLAIM。

| 方案 | 原研究记录 | 对 VAIWL 的约束 |
|---|---|---|
| ChatGPT Projects、搜索、Space | Projects 的聊天/文件/指令与上下文；搜索并非只有标题；研究记录 Space 与 Projects 有区别 | 不宣传原生只有标题搜索或完全没有工作空间；实际入口依账户验证，不能硬编码旧菜单 |
| AI Toolbox | 目录/子目录、多重加入、搜索、提示词、书签、同步 | 跨来源和多重归属并非独特卖点 |
| Superpower ChatGPT | 文件夹、全文搜索、分支、提示词、批量管理、收藏 | 不靠功能数量竞争 |
| Organizer / MarkBook | 自动文件夹、书签、ChatGPT/Gemini 整理搜索 | “AI 自动分类”并非空白市场 |
| Organizer & Workspace | 工作区、标签、笔记、树形对话、提示词链和本地搜索 | 不能只靠 Workspace 名称或大侧栏区分 |
| Sortbase | 多平台共同工作空间、文件夹、搜索、提示词和转移 | 不立即分散到多个平台的深度适配 |

不得合并两个同名 Organizer 的特性；Easy Folders 品牌关系在原研究中证据不足，不补写断言。原生 Space、模型语言与官方身份/用量路径均是动态记录，不作为当前资格或未来可用保证。

真正的差异假设是完整闭环：同一事项 → 稳定短名 → 正确系列/片段 → 恢复并行现场 → 原生继续工作 → 纠错不复发。未证明市场上无人提供，也未证明用户一定付费；需同任务对照。

## 4. 信息架构与选型

| 方案 | 优势 | 主要代价 | 研究选择 |
|---|---|---|---|
| 传统单归属文件夹 | 容易理解 | 把跨来源/多主题对话硬塞到一处，手动维护 | 不作唯一组织机制 |
| ACS 式当前对话邻域 | 随当前任务收敛、少管理 | 容易漂移，难以稳定回到长期事项 | 继承局部相关建议，不替代稳定工作区 |
| 自由动态聚类 | 自动化程度高 | 重跑会拆分/合并，用户空间记忆不稳定 | 不直接暴露自由聚类目录 |
| 稳定工作区＋系列＋工作集 | 长期身份与短期使用分开，可多重显示 | 需来源、约束与生命周期设计 | 本提案主方案 |

四个用户对象：Workspace 是长期事项；ConversationRef 是一个原生对话的引用；Series 是有证据的接续或分支；Workset 是眼下并行的少量对话。开发/设计/构想是可选分面，不是无限目录。相关对话是按需候选，不形成第五套必须维护的目录。

例：普通聊天中的 PAIA 开发、原生“paia 开发”项目中的实现对话、原生“产品想法”中的 PAIA 构想，可进入同一派生 PAIA。原生来源保留并可查。工作区内可省略已明确的 PAIA 前缀，全局搜索显示完整名称；这是同一 DisplayIdentity 的上下文呈现，不是两套独立标题。

对话多主题时优先加片段入口，不强拆、复制或频繁重命名。可定位消息/分支才承诺精确跳转；未知、未加载或不唯一时回到原生打开/查找。

## 5. 界面方案与原生保留

主建议：左侧导航＋中央对话/主动打开的概览；无常驻右侧 Inspector。卡片只服务少量继续入口，大量聊天用紧凑单行列表。进入现有对话时启动扩展不跳首页、不换路由、不抢焦点。新对话优先直接进入原生输入，而不是管理表单。

导航保留新建、搜索、当前工作集、少量常用工作区、全部已知对话、原生入口和恢复控制。原生全部功能的可达性是要求；是否汇总到“ChatGPT 功能”、模式开关位置、工作集呈现和概览默认动作仍待 PD-01/02/08 确认。

视觉继承原研究的中性浅色阅读面、轻边界、低干扰强调、仅少量导航毛玻璃。原型蓝白配色、228px 侧栏、顶部 58px 等只是示意，不是已批准最终像素。真实产品跟随原生深浅主题与减少动态；200% 缩放、对比度、读屏、IME 和窄屏必须另测。

## 6. 数据与产品边界

仅组织必要引用、命名、系列、布局状态与获准索引。不默认建立完整对话镜像；不读取助手正文、附件/Project 文件、未发送草稿做索引。仅有用户输入会有省略信息，允许未知，不补造上下文。

默认跨 Project 只限同一已核验账户和原生组织范围；不跨账户或组织混合。共享链接不是自有聊天，临时聊天不进入长期索引。官方导出是输入来源，不是聊天恢复 API；原生删除/权限变化后不可因本地快照继续冒称可导航或可分享。

PAIA 的 Input Archive、Thought Library、AI Context 与提示词复用仍由 PAIA 管；VAIWL 不复制。长期可显式映射同名主题，但名称相同不等于数据库同一对象或授权相通。

## 7. 能力路径与风险裁决

比较零散 DOM 增强、导航替换、完整克隆、独立后台、iframe 外壳、独立浏览器后，原研究选择“导航替换＋原生能力区”。完整克隆需追踪平台消息/工具协议；iframe 未有可靠证据且不可绕过防护；独立后台只适合低频导入/恢复/可信授权。

数据路径分拆为本地引用/别名、用户提供导出、经过审查的增量观察、独立云推理、受限原生改名。某条不成立只禁用那条，不能偷偷改用内部 API。用户同意、Chrome 权限、只读或竞品上架不替代平台条款与分发审查。

最早必须验证宿主身份而非先造漂亮 UUID；确认原生 DOM 岛与异常退出而非先搭完整 UI。R0 能力实验决定部署范围和后续依赖。

## 8. 旗舰终局与商业判断

完整目标包括真实获取路径、跨来源工作区、稳定标题/系列、工作现场、搜索/片段与纠错、原生恢复、用户资产恢复；在证据达标后加入高质量 AI、原生有限批次改名、端侧模型、加密可选同步及生态连接。阶段是依赖顺序，不是用 MVP 限制设计上限。

价值验证优先于按钮数量。若真实收益只有外观或手工目录，长期维护宿主适配的投入可能不值；若能稳定减少找回/纠错成本，才有独立付费依据。商店用户数不是自己的市场规模或收入预测。VAIWL 不依赖 PAIA 安装、不以锁住本地数据制造订阅价值；供应商、定价和商业身份接入都未选定。

建议的边界与未批准选择详见 [DECISIONS](DECISIONS.md)，具体依赖与成功标准见 [开发计划](DEVELOPMENT_PLAN.md)。
