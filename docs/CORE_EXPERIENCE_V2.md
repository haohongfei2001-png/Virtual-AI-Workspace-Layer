# VAIWL 核心体验增量 v2：原生一致性、主题卡片与用户输入时间

日期：2026-10-10。修订基线：提案 PR #1，`223a34f4b4f47d56b17b8d2c1cd3afa5a162101f`。原始研究与 v1 原型保持原件；本文件只新增/修订相关规格，不重启竞品研究。

## 1. 效力与边界

用户本轮明确要求以下三项成为核心体验（OWNER_REQUIRED）：延续真实 ChatGPT 视觉与交互；主题级卡片、卡片内紧凑对话列表；以可靠用户新发送时间驱动滚动日历窗口。不得再将它们标为“以后可能添加”或只放入后期美化任务。

它们补充而不推翻既有边界：Workspace 的稳定 ID、跨原生 Project 的只读引用、原生/派生标题分离、人工意图优先、独立账户与原生组织范围，以及保留原生聊天/输入/模型/工具。前台“主题”是已有 Workspace 的名称，不新增第二套 Topic/标签实体，不等同 PAIA Personal Topic。

本轮授权仅为设计文档、版本化交互原型及其合成测试。正式扩展、R0 宿主探针、私人账户读取、原生写入、模型调用、安装与部署未获授权。下文建议的精确排版密度、固定默认、展开数量属于设计解法，不冒称用户逐像素批准。

## 2. 原生一致性不是独立品牌皮肤

新增部分继承当前宿主的字体栈、字号层级、行高、权重、圆角、边界、间距、hover/selected/focus/disabled 状态、菜单锚点与关闭行为、动画时长和减少动态偏好。不迁入 PAIA 蓝白柔光、渐变、毛玻璃或大型品牌头图，不复制一个新的 ChatGPT 消息渲染器。

正式适配按已验证的宿主视觉角色映射 token：导航文字、次级说明、页面标题、行选中、弹出菜单、背景和边界。记录 Chrome/OS/页面语言/主题/对比度/强调色/缩放/宿主变体；不得将某次 CSS class 或本原型的像素值当长期平台契约。未知 token 使用克制回退并标为未校准，不侵入私有 React state，不下载字体或远程执行修复脚本。

菜单应匹配原生行为：就近锚定、越界避让、Esc 与外部点击关闭、焦点返回、方向键移动、Enter/Space 选择、可访问名称与读屏状态。实际宿主已有的菜单仍由原生负责；扩展菜单不能冒充账户、模型或官方授权控件。重要云/原生写入授权保留可信扩展界面。

第三方身份持续可见但低干扰：例如“VAIWL · 第三方扩展”，在窄屏也不只藏在已折叠侧栏。不能使用官方认证式标志、官方登录外观或不真实的原生能力按钮。关闭派生不是撤销已单独授权的原生改名。

**本轮证据限制**：定向读取 OpenAI 的 appearance 官方说明，确认主题、对比度和强调色是独立可变维度；未读取私人登录页面，没有完成当前登录态字体/间距/菜单动画的像素测量。容器访问公开网页的尝试受 DNS 限制；不以原型截图冒充真实 ChatGPT。v2 浅/深色是中性近似样本。R0 必须完成实际样本与角色 token 对照，之后才能称原生视觉验收。

来源：[OpenAI visual experience](https://help.openai.com/en/articles/11958281-updating-your-visual-experience-on-chatgpt)，本轮定向读取；[ChatGPT 公共页面](https://chatgpt.com/)，仅公开页面文本，不等于登录态 UI。没有重做市场研究。

## 3. 主题卡片与紧凑列表的关系

“不要把每条对话做成大卡片”继续有效；“只用无边界平铺列表呈现所有主题”被本次要求替代。正确结构为：一个稳定主题一个卡片，卡片内部是紧凑对话行。普通聊天及不同原生 Projects 中的相关对话在同一卡片出现，点击仍进入同一原生 conversation。

主主题视图由人工固定（存在时）、区间活跃主题、折叠的历史/区间外主题、折叠的时间待确认区域组成。每个区域只有同一套主题卡片，不是新的归属目录。一个主题在这些区域间只显示一次；跨主题的同一对话可以有多个 Placement，但底层 ID 与消息不复制。

卡片头：主题名称、展开控件、区间命中/已知对话数量、按需菜单。边界与留白分隔主题，不使用主题专属大面积彩色背景。活跃不等于当前选中：当前主题用选中描边/状态，时间活跃用实际命中计数/文案，不能用一个闪烁圆点混淆两者。数量只针对已知引用，不宣称账户总量。

卡片内：区间命中对话优先，紧凑行展示可区分的派生标题、必要的原生来源以及最近一次**该区间内**的可靠用户发送日期。辅助来源在多 Project 卡片和对话页可查。正文不裁剪保存，标题只在显示时省略。未核验 Project 不标为普通聊天。

展开/折叠只改视图状态。建议初始最多 4 行；“再显示 12 条”可一直到当前集合真正末尾；主题有几十条时提供“单独查看此主题”，仍是同一卡片/同一 ID，不新建文件夹或复制会话。卡片内不设又一层独立滚动栏。原型演示 1/2/3 列响应布局；列数和行密度仍属待视觉评审的解法，不是用户硬限制。

历史或区间外子对话在主题内单独折叠；时间待确认另行折叠，不能用历史命名掩盖未知。查看过去区间时，“区间外”还可能包含更晚的对话，不能全部称为更早历史。建议按区间内最近用户发送时间排序，人工固定顺序另行保持；点击/hover/菜单打开/IME 期间不自动重排。

## 4. 时间窗口：以当地今天为锚点

采用公历 PlainDate 语义与 IANA 时区 Z，不采用自然月、自然年、30/90/365 天或固定毫秒时长。T 为用户当地今天；长度 m 为 1、3 或 12 个月；k 为向过去的段号，最近段 k=0。

定义 B(j)=从**同一个 T**减 j×m 个日历月，目标月无该日则夹到月末。不得从上一次夹过的边界继续减月，以免 3/31→2/28→1/28 漂移。

- 最近段：起日 B(1)，结束日 T，日期集合 [B(1), T+1日)。
- 过去第 k 段（k≥1）：起日 B(k+1)，结束日 B(k)−1日，日期集合 [B(k+1), B(k))。
- 展示两端均为包含日期；内部用左闭右开的当地日历边界。相邻段无重叠、无缺日。

T=2026-10-10 时：

| 长度 | 最近段 | 上一段 |
|---|---|---|
| 一个月 | 2026-09-10—2026-10-10 | 2026-08-10—2026-09-09 |
| 三个月 | 2026-07-10—2026-10-10 | 2026-04-10—2026-07-09 |
| 一年 | 2025-10-10—2026-10-10 | 2024-10-10—2025-10-09 |

这遵循用户明确示例：最近段包含今天，历史段止于下一边界前一天，不保证每段固定天数。2026-03-31 的最近月段为 02-28—03-31，上一段为 01-31—02-27；闰年/闰日同理。

“全部历史”不作时间剔除，展示全部已授权已知引用，包括时间未知与未归类；不把未知记录标成活跃。禁用前后分段按钮，因为无限历史没有等长上一段。改变长度默认回到 k=0，并显示实际日期；保留当前对话、人工归属和固定项。

发送 instant 必须具有明确时区/偏移，转换到 Z 后比较当地日期。夏令时按当地日历处理，不减固定 24 小时当作一天。原始 instant 不因时区变化被重写。无偏移时间、格式错误、冲突或不合理未来时间进入待确认，不任意解释为本机时间。

正式产品在当地午夜、系统时区变化、休眠唤醒/页面重新聚焦时重新求 T 与窗口；事务化计算新投影，不在 IME/拖动/打开菜单期间跳走或移除当前对话，必要时提示待应用的日期更新。历史浏览若需要固定锚点，必须显式标“截至某日”，不能悄悄停止跟随今天。v2 为可复验而固定“示例今天”，提供日期/时区控制；不声称已经实现宿主午夜调度。

## 5. 活跃性：事件存在性，不是最后更新时间

`active(c,W)` 当且仅当该对话存在至少一条：范围/对话/消息身份相符、作者为用户、确已新发送、拥有可信原始发送时间且落在 W 的消息事件。主题活跃当且仅当当前有效成员中存在这样的对话。消息正文不必为时间筛选重复保存。

**只存 lastUserSentAt 不足以支持向前分段。** 一个对话 8 月和 10 月都有输入，查看 8 月时仍必须命中；取全局最后一条会漏掉它。需要逐消息事件、可靠分段索引或能回答存在性查询的等价可追溯索引；区间内最近时间只用于排序与显示。

不采纳：访问/open/focus 时间、用户按下发送但未确认成功的时刻、AI 回复/流式结束、标题变化、Project/主题分类、固定/解固定、导入/观察时间、聊天级 updated_at。用户后来修改消息不能直接用修改时间冒充原始发送；若是一次明确的新提交事件，须有独立新发送证据。重复导入/响应按复合消息身份去重。

归属纠错不制造发送事件，也不将操作时间写成活跃时间；但主题成员真的改变后，其对真实用户事件的汇总可能自然改变，这与“用分类操作激活主题”不同。时间切换本身绝不写 Placement/主题归属/原生 Project，也不删除记录。

可信来源候选：已核实原始消息级发送时间的官方导出或被授权的真实宿主证据。来源角色、scope、消息 ID、时间语义及覆盖均须 R0 验证。导出文件日期、DOM 中“昨天”、浏览器时钟看到消息的时刻不能自动提升为原始发送时间；没有证据就保持未知。

## 6. 三态与覆盖范围

- IN_RANGE：有可靠的区间内用户发送事件；即使全文/其他时段覆盖不完整，这个正向证据也有效。
- NO_SEND_IN_RANGE：该区间在有效完整性证据覆盖内，且没有命中事件；可称该区间不活跃/区间外。
- UNKNOWN：没有正向命中，同时缺少足以证明无输入的时间/覆盖证据，或相关时间冲突/过期。

有一条很早的可靠消息，不证明最近一个月没有更新。旧快照不能证明快照之后至今无新输入；至少按 `completeThrough`/coverage intervals 标记未知。完整性只相对于所验证的快照/分支/范围，不意味着永远看见全账户。正文完整性与时间索引完整性应分开。

主题：有任何 IN_RANGE 成员则活跃；没有 IN_RANGE、但有 UNKNOWN 成员则时间待确认；只有所有可判定成员均 NO_SEND_IN_RANGE，才进入已确认区间外。未知记录有可展开的入口和数量，不消失，也不混入活跃统计。“全部历史”只是 ALL_VISIBLE，不是第四种活跃证明。

## 7. 当前使用、人工固定与未知记录

当前对话是可见性例外，不是时间事实。打开旧对话后保持当前路由、原生聊天节点、输入框、草稿与已知阅读位置；时间切换/卡片折叠/日期变化不把它关闭。提供“正在查看 · 区间外/时间待确认”访问条和工作集入口；不自动激活其主题，也不自动打开历史区造成版面大跳。获得一次可信新发送后再按事件自然更新。

建议固定语义：固定主题在独立低干扰固定区常驻，不重复出现在活跃/历史区；明确显示区间外或未知。固定对话在其主题内可见，必要时带出父主题为“含固定对话”的访问例外，不伪造主题固定意图或活跃性。解除固定后回归正常投影。固定与当前状态永远不能绕过账户、组织、权限撤销和不可达校验。

原型为验证采用上述固定例外；是否使用单独固定区、自动保存现场及精确位置仍待评审。不得以这项待定为理由不设计/测试例外规则。

## 8. 数据与投影增量

新增逻辑契约，不是本轮 DDL 或正式实现：

| 对象 | 最小信息 |
|---|---|
| UserSendEvent | scope、conversation、branch/message ID、originalSentAt、offset/precision、author/send-state evidence、来源/版本、timeQuality、dedup key |
| TimeCoverage | scope/对话/分支、覆盖区间、completeThrough、快照/来源版本、有效性；与正文 coverage 分离 |
| TimeWindow | months/all、offset、anchorLocalDate、timeZone、[start,endExclusive)、policyVersion |
| ActivityProjection | queryKey、输入 revision/epoch、对话三态、主题三态、区间内最近事件引用、数量/完整性；可重算但不覆盖源数据 |
| VisibilityException | scope、对象、human pin 或 current-session、显示理由、人工顺序；不含伪造发送时间 |

计算顺序：权限与 scope → 时间证据查询 → 对话状态 → 按当前 Placement 聚合主题 → 固定/当前访问例外 → 同一 revision 的卡片/内列表/数量一起提交。旧窗口、旧时区或旧账户的异步结果拒绝；不能先用新主题数量搭配旧对话列表。

缓存键至少含 scope/epoch、窗口、anchor/timeZone、time-policy、事件/coverage/placement/固定 revision。事件被修正、删除、撤权或覆盖失效后同步失效；不反向删原生消息，不因活动索引清除破坏独立人工名称/归属。时间元数据和关系也属于敏感信息。

## 9. 点击与安全恢复

正式扩展点击已知对话沿用经验证原生链接/原生导航路径，核验 account+native-space+conversation 后才聚焦既有 tab；保持 modifier/middle click 语义。跨 Project 引用不搬移原生归属，不复制正文，不暗示项目上下文合并。

不移动/克隆原生 transcript/composer；只撤销自有导航、样式与挂载。切换时间不是重新渲染原生聊天的理由。正常关闭与故障回退分别测试。浏览器禁用/卸载后未必仍有清理 JS；不得自动刷新用户工作页面来制造通过。

v2 中相同对话切换窗口/模式时保留同一模拟 textarea/transcript 节点，并验证内容和 selection。它不是实际 React/ChatGPT DOM，也不证明真实扩展 disable/reload、实际标签页、IME、账户或 PAIA 共存。保留这种区分。

## 10. 提前进入开发主路径

R0-00 增加原生视觉样本/角色 token 盘点；R0-02 必须证明消息级用户发送时间与时间覆盖来源，并给出不可得时的 UNKNOWN 行为；R0-04 增加时间切换与原生节点、焦点、草稿连续性；R0-05 同时检查主题导航与 PAIA 浮板、输入框增高及菜单占用。
