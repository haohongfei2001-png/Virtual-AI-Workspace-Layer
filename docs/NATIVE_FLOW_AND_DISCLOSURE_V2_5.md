# VAIWL v2.5：轻量回看、就近返回与原生聊天所有权

2026-10-10。基于 Draft PR #1 / `fdd1550a325ea44c81107e6e1592b70c2a059c4b` 和已读取、核验的 v2.4 原型增量修订。用户认可总体方向并提出五项进一步要求；这不是所有旧候选像素、容量或执行权限的整体批准。

## 1. 保留什么，修正什么

保留主题卡片、不同但同族的单色图标、当前主题展开的连续侧栏、其他活跃主题默认折叠、用户自主控制侧栏、原生数据与 Project 不变。时间与归属继续以 CORE_EXPERIENCE_V2_1 为准：主题按最近可靠用户新发送独占一个滚动日历段，旧窗口依附父主题，未知时间不伪造，访问与改名不激活。

本次修正 v2.4 的三处具体解法：选中行左侧黑色内描边；把活跃预览溢出、旧窗口和未知窗口都塞进“全部对话”；让用户经过“全部主题”集合页才能逐段回看。返回工作空间不再只能从侧栏底部寻找。其余无冲突设计继续适用。

## 2. 选中态不是另一层容器

旧原型 `.side-children .row.is-current` 使用 `box-shadow: inset 2px 0 0 var(--text)`，圆角使它看起来像选中窗口左侧半个黑括号。本次删除这一内描边，只保留浅色/深色主题下的中性选中底面和 `aria-current`。

删除的是选中装饰，不是键盘焦点。保留 `:focus-visible`、清楚的焦点状态和主题/窗口的结构区分；原有低对比从属线不因为删除选中黑边而全部抹掉，不退回仅靠字号和字重辨认。

## 3. 主题内展开：一个有明确含义的“以前”

候选使用卡片/侧栏列表下方的轻量“以前＋向下折叠箭头”。箭头随展开旋转，文字不反复切成另一个分类；展开仍在同一主题内，点击同一控件收起。不显示数量、日期或来源，不用省略号菜单来伪装历史入口。

纯向下箭头可以表示展开，但无法单独说明下面是更多活跃窗口还是旧窗口；纯省略号也容易与操作菜单混淆。因此保留最短的时间语义词“以前”，而不是声称无文字图标天然可理解。这是待体验评审的具体解法。

该控件只展开已经能够确认属于该父主题较早阶段的窗口。它不能顺带展开尚未露出的活跃窗口，也不能把未知时间记录当作不活跃。默认日常 PAIA 的五个当前窗口直接可见；点击“以前”只增加两个旧窗口，不再混入一个未知窗口。

大量活跃窗口仍可在当前列表尾使用“显示更多”，这是容量动作，位于当前列表内部；它不归入“以前”。首页五行、侧栏八行和后续批次大小仍是候选参数，不是用户已批准的硬上限。历史展开同样能逐批到达末尾。

时间未知的记录没有删除：搜索默认覆盖已保存对话，主题菜单增加“查找此主题的对话”，可查该主题全部成员；工作空间选项中的“查找所有记录”保留中性集合页和未分期材料。未知记录不在日常界面形成第三个并列展开任务，也不贴假历史标签。未知窗口被直接打开时，以“正在查看”的单一访问例外定位，仍不增加活跃时间。

## 4. 工作空间回看：直接走向更早，不经过总目录

首页底部的主动作从“全部主题”改为轻量的“看看以前”按钮；点击直接显示前一段非活跃主题。下一段仍用相同按钮位置，文案变为“再早一些”。用户无需理解一个月的精确起止日期，后台仍严格执行已经确定的日历窗口，不能改为模糊的随机历史分组。

回看时只增加紧凑的“返回”“回到现在”路径；前者走回相邻较近段，后者回到近期工作空间。不重新加入日期工具栏或大标题。卡片只有一张时，回看按钮随卡片内容宽度对齐，不漂浮在另一半空白画布中央。

每次只前移一个相同长度区间，不因为某段没有记录就悄悄跳过。空段允许继续前移（若已知还有更早记录）；没有更早的已知记录则结束，不制造无限空页面。“最早”只指已知集合，不声明读取了完整账户。未知记录不能被自动塞进最早日期段。

“查找所有记录”是次级查找入口，包含当前、历史与未知；“看看以前”是日常逐段回看。两者不再平级占据主页。历史主题和当前主题继续互斥，窗口不能独立从父主题跑到别的月份。

## 5. 聊天必须就是原生 ChatGPT

这是所有权边界，不只是看起来像原生：正式产品点击真实对话引用后，通过核验的原生链接/路由进入 ChatGPT 原会话。消息正文、输入框、模型选择、附件、语音、工具输出、停止/编辑、打字与生成动效等继续由 ChatGPT 渲染、更新和处理。

VAIWL 拥有工作空间和派生导航，不拥有第二套聊天运行时。不得复制 transcript 或 composer，不用抓取文本另画会话，不接管发送/流式响应，不用自制动画覆盖原生生成效果；也不将原生会话改为扩展页面 URL。原生 Project 上下文与权限不因主题聚合而改变。

派生名称在 VAIWL 的卡片/侧栏中使用，不为展示别名而主动改写原生聊天标题区域。实际原生标题修改仍须独立授权。关闭扩展、切换时间、更换主题图标或改显示名不重建原生输入框，也不重放任何聊天操作。

生产样式只作用于扩展自有区域。宿主 font/color/radius/menu/motion 参照经验证的原生角色，不操作私有 React store，不全局覆盖原生按钮、动画或 reduced-motion 行为。原型中为静态演示提供的全页 CSS 和 mock 渲染器不得作为产品聊天实现直接迁移。

离线 HTML 无法装入用户的真实登录会话。本次将聊天示意明确隔离为 `native-fixture`：无派生标题头、无工作集横条，原型内部只在模拟切换对话时建立样本；同一对话下的图标/名称/模式/时间切换保持同一示例正文与输入节点。它仍然不是原生接入的证据。dot 也仍只是原生入口示意，实际可用性待 R0。

## 6. 返回工作空间：位置稳定，动作明确

| 方案 | 裁决 |
|---|---|
| 只留左下角返回 | 难在进入聊天后立即发现，不作为唯一入口 |
| 点击 ChatGPT 标志就回 VAIWL | 偷换原生标志行为，不采用 |
| 聊天正文上再叠一行返回横栏 | 与之前去重复顶部相冲突，不采用 |
| 侧栏既有顶部增加“工作空间”入口 | 当前首选，不增加新横栏，开合按钮仍独立 |
| 折叠侧栏顶部保留同一工作空间图标 | 当前首选，鼠标提示及无障碍名称说明用途 |
| 劫持浏览器后退/触控板返回/Esc | 不采用，原生导航、菜单和输入行为优先 |

展开侧栏时，“工作空间”位于已有侧栏顶部、ChatGPT 文字旁，单击返回；不是把 ChatGPT 标志重新绑定。折叠/窄屏导航轨在靠上位置提供相同入口。它返回刚才的工作空间位置，不关闭 VAIWL，也不等同于“回到原生”。

返回锚点包含来源视图、历史段、主题上下文、展开状态、滚动和原入口。通过侧栏在聊天 A/B 之间切换，不应丢掉之前的工作空间锚点。从外部直达聊天而没有锚点时，回到当前工作空间。用户的侧栏开合偏好继续保持；窄屏明确返回工作空间时可关闭遮罩，让内容可见。

浏览器本身的后退继续代表访问历史：A→B 后退应回 A，不能被扩展强行改成工作空间。原生路由与派生视图的返回关联只能在 R0 有实际路径证据后设计，不能通过伪造 history.state/拦截所有后退解决。本原型没有实现或验证真实浏览器/ChatGPT 路由后退。

## 7. 工程落点与批准边界

C1 从首次完整体验采用清楚区分的“当前列表容量/以前窗口”结构及逐段历史入口；C2 保持真实原生区域所有权和顶部工作空间返回；C3 保存必要的视图返回锚点，不保存原生草稿或运行态。B3/B4 区分派生UI偏好与成员归属、真实时间证据；未知时间依旧遵守范围与覆盖约束。

R0 的真实宿主验证需包含原生节点保留、原生模型/输入/工具/动效不被覆盖、原链接与前进后退语义、工作空间恢复、当前历史窗口与实际 PAIA 共存。不得将本次离线原型通过改写成上述能力已经实现。A–G 与唯一 R0 任务不另起一套。

用户已表达总体认可；连续侧栏、原生聊天、不用黑色半边选中边、自然展开与回看、易发现返回是本轮要求。具体“以前/看看以前/再早一些”文案、上方入口像素和容量仍为候选。只允许设计/原型修订，不扩大为正式实现、安装、私人聊天、云调用或真实原生写入授权。
