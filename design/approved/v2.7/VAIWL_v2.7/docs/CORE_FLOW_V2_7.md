# VAIWL v2.7：上下分段、持续展开与单一阅读返回

2026-10-11。基于 PR #1 / `7ff85d2fdf3abf9035404c8642c209cce2af1051` 和核验的 v2.6 原型定向修订。本轮只设计及离线合成验证，不实施正式扩展。

## 1. 本轮替代关系

用户本次明确提出六项修订：不用时间回转图标；以30天上下切换主题，当前段没有向上；主页主题不折叠；旧窗口展开不居中；核心之外尽量原生；检查最新网页版遗漏；阅读区用一个无常驻文字按钮返回工作区。

这不是重新研究。v2.1 的主题唯一最近活跃归属、父子关系、未知时间及人工修改优先仍有效；但其中“滚动日历月”被本次明确的固定30天替代。v2.6 的时钟回转、居中把手以及侧栏顶部/折叠轨工作区入口均被替代。具体边距、列数和图形的初见理解仍待体验，不自动声称经过真人验证。

## 2. 固定30天，主题只能属于一段

使用用户本地日期T；先将可信发送instant转换到同一IANA时区的本地日期。段k定义为 `[T+1−30(k+1)日, T+1−30k日)`，k≥0。包含今天在内的最近30个日历日是k=0，不是自然月，也不是前30×24小时；夏令时不改变日历日个数。

示例T=2026-10-10：当前09-11—10-10；上一段08-12—09-10；再上一段07-13—08-11。每段恰好30日，连续无重叠。这个改变会影响9月10日等边界项，不能为了维持旧测试数字而修改原发送事件。

主题取成员最近可靠的新用户发送，只落入一个段。当前段有可靠正向事件即可；判定较早段仍须可信覆盖排除更晚输入。旧快照不能证明截至现在没有新发送。未知记录经全记录查找保留，不能塞到最早段。访问、图标、改名、分类、固定、保存临时聊天等动作不产生新用户发送。

上下切换只选择投影，不修改Workspace、Placement、原生Project、消息或标题。旧窗口仍附属于其父主题，不按自身月份另造主题。历史主题再次有新输入时整组进入当前段，旧成员继续折叠。当前访问和固定是可达性例外，不改变时间归属。

旧1/3/12月控件从本版常用选项移除，避免一个产品同时执行两种切割逻辑。完整已知记录仍能查找。未来其他跨度需明确设计，不把360天写成一年。

## 3. 上下导航，而不是历史管理页

原型在主题区外侧右缘设置窄幅纵向按钮区。下箭头进入k+1；只有k>0时才有上箭头进入k−1。最新段不渲染向上按钮，不留灰色禁用的占位。历史段也不增加时钟、返回当前小房子、月份或计数。

空段不静默跳过；仍可向上，若已知还有更早内容则可向下。最老的已知段可禁用向下，但不能据此宣称全账户历史已经穷尽。底层未知记录保留独立查找路径。原型样本为有限集合，生产必须另有渠道覆盖说明。

按钮有aria-label、键盘焦点和简短辅助提示，常态无文字。不能将鼠标滚轮、PageUp/Down、方向键或浏览器Back/Forward劫持为时间翻页。用户仍正常滚动页面。右缘的窄按钮区不占聊天正文空间。

## 4. 主页主题始终展开；侧栏仍可折叠

主页主题标题改成静态h2，不是按钮，删除头部折叠箭头及“只看主题/折叠全部”。近期窗口直接出现在主题下。取消的是主页整卡折叠，不是其他活跃主题在聊天侧栏里的折叠，也不是旧窗口的隐藏。

主题头区、同族稳定图标、轻边界、缩进保持层级；不能退回仅靠粗体字号。主题菜单保留必要的纠错、查找、图标等操作。大量近期窗口的容量由近期列表内“显示更多”处理，不伪装成旧窗口。原型保留5行预览/12行增量的候选容量，并可到真实集合末尾。

## 5. 旧窗口入口在列表左侧延续处

删除居中底部胶囊。旧窗口入口改为贴着列表缩进基线的侧向小箭头：折叠时向右，展开后旋转向下，内容在原主题内出现。主页与聊天侧栏沿用相同语义和位置关系。

它只展开已确认较早的窗口；不混入未显示完的近期窗口，也不把未知时间说成历史。没有旧项就没有空按钮。大集合可继续加载至末尾。按钮视觉克制但实际命中区不缩到几像素，键盘焦点保留，展开后焦点不退回主题头。

所选窗口仍只有中性底面，没有左黑色内描边或半括号。主题从属线保持低对比，不能因去掉选中装饰损失层级。

## 6. 阅读区只有一个工作区返回入口

在阅读区域左上角、原生头部外侧的已验证空位放一个四格工作区图标，无常驻文字。按钮属于VAIWL，不冒充原生功能；与原生ChatGPT/模型按钮并排但不改绑它们。删除侧栏顶部、折叠轨、底部及专用页重复的VAIWL工作区返回。

同一图标在侧栏展开或收起时都可达；不需先展开导航。点击恢复刚才工作区的历史段、滚动和旧窗口展开状态。工作区主页不显示该返回图标。专用原生页需要退出VAIWL导航时使用同一个实例；原生自身的返回或浏览器历史不删除、不改义。

原型为模拟宿主预留了槽位，正文/输入节点没有因此重建。正式产品必须验证该插槽不与模型、分享、停止、Canvas等控件重叠。若当前变体没有可靠空位，先报告布局受限，不能覆盖原生控件或在多个角落自动堆替代入口。

## 7. 核心之外保持原生

VAIWL拥有主题总览、派生侧栏列表/名称/图标、确定性分段、历史展开和唯一返回。真实ChatGPT拥有正文、输入、模型、工具、流式生成、交互回复、原生动效、任务/授权状态、资源专用页和账户。保留真实节点和生命周期，不截图、不复制HTML、不重画聊天，不用通配CSS修改原生组件。

原生新聊天、搜索、快捷键、dot和用户头像/字体、用户已固定对象按实际宿主保留。低频原生功能如需折叠优先保留原生组织，不为追求统一再建VAIWL版菜单。头像可有原生颜色，扩展单色规则仅约束扩展自己的主题图标。未知新入口默认保留；停用能力不能从旧名单重新画成可用。

新版的定向补漏见 [NATIVE_WEB_DELTA_2026_10_11](research/NATIVE_WEB_DELTA_2026_10_11.md)。官方说明证据和当前登录态证据分开。原型菜单是合成宿主，不是对用户账户现状的还原。

## 8. 原A–G任务的增量验收

不建立第二套执行队列。以下是DEVELOPMENT_PLAN同名任务的修订条件；旧月窗口和整卡折叠条目由本节覆盖。

- R0-00/04：当前宿主功能/状态清点；确认唯一阅读返回槽位、原生控件不遮挡；交互回复的局部状态不被派生重绘破坏。
- R0-02、B2/B3/B4：可信用户发送与覆盖不变；时间规则版本明确为固定30当地日历日；新旧规则迁移只重算投影，保留原证据和人工意图，不重发消息。
- C1：主页无整卡折叠；上/下分段、最新无向上、左侧旧项展开、未知可达。主界面不显示日期/来源/计数。
- C2：原生为默认所有者；一个阅读返回实例；保留原生搜索、固定聊天及项目、临时聊天保存/个性化、资源权限及待处理状态。
- C3：恢复来路与原生状态；不接管浏览器Back/Forward，不恢复Agent内部运行态。
- C5/C6：上述从首次完整界面实施，最终只回归；真人图形可发现性、物理IME和真实宿主兼容仍须验证。
